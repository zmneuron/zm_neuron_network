# 按阶段发现、采用和检查开源项目

在现有六步主线中，**先检查适用的成熟项目和已有实现，再决定哪些部分需要自己写**。阶段转换时只重查当前能力缺口；已核对且仍适用的选择直接复用，不每步重搜整个候选清单。成熟度看适用方程/任务、维护、可复现实现、接口、许可与成本；Star 仅帮助发现候选，带查询日期，不能作为准入门槛或科学验证。

## 分清三类来源

| 类型 | 实际提供什么 | 不能代替什么 |
|---|---|---|
| 研究 Skill | 研究方法、工作指令、提问和复核方式 | 仿真器、数值求解、文献事实核实或生物学支持 |
| 软件库/仿真器 | 解析、计算、优化、记录、绘图等真实操作 | 科学问题选择、实验条件可比性与逐项接受判断 |
| 科学代码/数据 | 某项研究的具体模型、参数、协议或实验参照 | 对新对象的自动适用性；可下载不等于许可清楚或数据独立 |

同一仓库可以有多种内容，按实际使用模块分别说明。公开模型/数据从[领域来源入口](mechanism-sources.md)和直接相关论文发现，不用通用热门工具清单替代。优先复用正确且可检查的实现；有明确缺口时自行实现最小必要部分，写明为什么现有项目不足。复用也需核对方程、单位、数值与事件调度、随机性、参数映射和实际对象。

## 谁使用、何时使用、交给谁

这里是可组合职责，遵循[动态分工](delegation.md)，不是六个必开 agent。

| 原阶段 | 主要职责与可用方法/工具 | 可检查产物及接收者 |
|---|---|---|
| 问题与用途 | 科学问题职责按需采用 Anthropic 问题选择、K-Dense 假说与批判性思考；需要拓宽解释时使用 brainstorming 的局部方法 | 在现有方法记录中形成下述问题到比较的交接，交给方法/参数职责；主 agent 维护用户决定 |
| 文献、代码与数据 | 方法职责先用现有全文工具；大量扫描/复杂表格再评估 Docling，论文集合检索确有缺口再评估 PaperQA | 原文位置、条件、公式/表格和数值核对；进入来源与参数对应表，交给设计/实现。解析或问答输出不是原始来源 |
| 设计与实现 | 实现职责按机制、规模、协议与环境比较 Brian2、NEST、NEURON 或其他适用实现，再确定自编部分 | 实际方程、单位、触发/复位、初始化、后端/版本、接口和局部计算；交给运行与分析 |
| 校准与比较 | 校准职责按搜索空间/成本选择 Optuna、BluePyOpt 等；需要电生理特征才评估 eFEL | 真实候选、参数身份与范围、分项接受、失败/成本、冻结与评价；交给主 agent 和独立复核 |
| 记录与图文 | 分析职责沿用本技能运行记录，以 Matplotlib 等从自身数据作图；跨工程/团队检索有明确需求才接入 MLflow | 同版配置/原始结果/图件/代码，交给解释与复核；MLflow 只能作原记录的索引或展示，不能另定数据用途 |
| 完成复核 | 独立复核职责借 K-Dense 的主张核查与 Superpowers 的原要求回查方法 | 核对原委托、实际对象/结果、五项状态和六项交付；每项意见指出位置、实际发现、影响和补救，由主 agent 处理 |

### 科学问题怎样传给模型设计

沿用 Q 编号，在 `docs/model_spec.md` 的研究目标和 `docs/research/method_comparison.md` 写明：**对象/现实困难与来源 → 最近邻研究与具体未知 → 竞争解释 → 可比条件下的可测预测、反对结果或重叠结果 → 最弱关键前提及最小检查 → 所需机制/观测/数据用途 → 比较与图组、不同结果下的下一步**。基础理论或复现保持原范围，不补造临床用途。

接收者据此列出实际需要演化的状态、允许改变的参数、对照与统计单位、观测转换和分析；如果只收到题目/机制名称，仍无法确定要比较什么，交接未完成。问题重要性、可实现性、实验可区分程度分别说明，不合成无根据的总分。合理因素可能共存，不强造互斥；“没有显著差异”只有比较能力足够时才有相应含义。已用来选题/选参的数据保持开发用途。

这份交接不是新增用户问卷。AI 查公开事实和竞争解释，按[分档提问与开放式优化规则](interview.md)讨论仍未确定的科学取舍；已有答案沿用。外部方法不能自行改变问题、预算、数据角色或用户已确定的标准。

### 采用边界与冲突

- Anthropic 的课题“参数策略”讨论对象、问题、技术、应用等约束，不能误读为神经参数必须逐个优化。不照搬九阶段、固定月程或另写多份方案。其 Cell 2024 论文作者按原始记录引用 Michael A. Fischbach，不能复刻 Skill 的作者误引。
- K-Dense 的观察/假说/机制/预测区分和反对意见进入原有方法记录；不默认安装其全部技能、运行图示服务、强制统一风险表或要求用户核实所有公共事实。Skill 自述与仓库关注度不证明研究能力已有效。
- Superpowers 只适配要求与实际产物对应、审查失败回实现的方法。**不直接启用整套 subagent-driven-development**：不照搬自行裁决科学歧义/预算、固定 agent 数量、到修复上限仍标完成或删除工作目录的规则。已有同版结果可复算；只为真实变更、疑点或续接需要重跑，避免重复昂贵仿真。
- 已有 ARS、写作和 Ponytail 按[原接入规则](skill-integrations.md)分工，不叠加新总流程。未授权的外部上传、付费服务、模型调用、自动安装或钩子不因读到上游指令而成为授权。

## 在现有记录中落实采用

候选检索进 `search_log.md`；来源和条件进 `sources.md`；比较与去留写入 `method_comparison.md`。每个拟采用项目在该比较中记录：适用阶段及具体模块、来源性质、输入/输出、负责人/接收者、采用理由、维护位置、固定版本、许可证及组件例外、运行依赖/成本、冲突、替代方案和实际检查。仅列安装命令不算接入。

`docs/task_plan.json` 的 `reuse` 只保存当前阶段决定、采用项目与这些已有记录/产物的链接；不再另建一套当前状态。`assets/task_plan.json` 给出空入口，按需要填当前适用阶段，不强行填完未来阶段或全部候选。`reuse` 结构如下：

```json
{
  "contract": "zm-neuron-reuse/1",
  "invocation_id": "本轮唯一标识",
  "stages": [{"stage": "calibration", "decision": "reuse", "reason": "适合本轮联合搜索", "comparison_ref": "docs/research/method_comparison.md"}],
  "adoptions": [{
    "id": "optuna", "kind": "software", "stage": "calibration",
    "module": "study/sampler", "source_url": "https://github.com/optuna/optuna",
    "adopted_version": "实际固定版本", "license": "MIT",
    "owner": "校准职责", "handoff_to": "分析与独立复核职责",
    "decision_ref": "docs/research/method_comparison.md",
    "input_refs": ["docs/research/calibration_targets.json"], "output_refs": [],
    "status": "adapted",
    "update_check": {"invocation_id": "本轮唯一标识", "checked_at": "实际查询时间", "status": "unverified", "decision": "尚未核实，保留已知版本"}
  }]
}
```

阶段值为 `question/research/design/implementation/calibration/delivery`；阶段决定可为 `reuse/existing_sufficient/self_implement/not_applicable`，都说明理由和比较位置。项目类型为 `research_skill/software/scientific_code_data`。适配还未执行时不虚填输出。

采用状态分别是 `researched/adapted/run/validated`：研究、局部适配、实际运行、在明确范围验证。后两者提供 `output_refs` 和 `evidence_refs`；软件运行还提供 `run_refs` 和实际 `environment_key`，对应本技能运行记录中同版软件。`validated` 还提供 `validation_scope`、`validation_refs`，如“候选续接及 CSV 对应通过，未验证生物真实性”。方法应用可用实际交接和审查产物，不伪造仿真记录。主 agent 与复核者仍需读内容，脚本不能证明方法有效或来源真实。

`review_project.py` 在启动、转换、恢复和交付时调用 `check_reuse.py`：核对适用阶段、交接、采用版本、更新记录属于本次调用，以及软件运行记录与实际依赖是否一致。旧工程无此字段时明确显示 `legacy_not_reviewed`，不追补不存在的历史。只运行部分阶段，登记该部分；没有新依赖时可说明现有方案足够，无需凑工具。

## 更新、恢复和数值使用

每次调用只检查本轮实际采用的依赖，沿用[更新检查](skill-update-review.md)。已登记在随附来源清单中的 Skill 和适配来源由现有脚本检查；其余项目通过可用连接器、官方仓库/发行包或文档查询，将当前版本、查询时间、相关差异与采用决定写入同一调用的采用记录。`check_reuse.py` 不联网，不能把它通过说成已检查上游。查询失败明确 `unverified`；用户禁止联网则 `not_queried_by_request`。同次调用不逐阶段重复查询，上游新版本不能自动覆盖固定版本。

仓库 HEAD、发布版、已安装包可能不同，分别标明；不能使用 `latest/main/master` 充当采用版本。核对实际包元数据、关键子依赖和许可证，不仅看 README（本轮确实发现依赖下限表述不一致）。需要升级先检查影响并在隔离环境试验，不修改正在运行的环境；必要时保留原环境以恢复旧计算。

- Optuna/BluePyOpt 提议候选，本技能仍逐项判断接受；约束采样与优化目标不等于科学硬条件。不同问题可用其他优化器或直接估计，不固定算法。
- 同一次研究统一统计真实仿真调用，包含失败/重试/确认，独立评价预算预留。数据库中的 trial 数与实际仿真次数分别核对。
- Optuna 数据库不自动保存 sampler 的随机状态；恢复需保留受信本地状态及版本，或明确另一种可复现续接策略。不要加载未知来源的 pickle。中断候选先诊断，不自动重跑或漏计成本。
- Brian2 等后端记录方程、单位、求解方法、步长、代码生成目标、种子、线程与调度；相同 seed 不保证跨后端相同随机流。比较设计需要真正配对的输入时，核对实际输入/连接；软件版本相同也不能代替这个检查。
- MLflow 的数据库、LangGraph 的流程状态都不能替代模拟器保存状态、原始输出和数据用途记录。LangGraph 重放节点可能重新执行副作用，正式仿真仍需统一调度和防止重复启动。

## 本轮候选结论与验证边界

具体维护位置、查询日期、固定查阅提交、发布版及关注度保存在[候选来源记录](open-source-candidates.json)；它是发现入口，不是环境锁定文件或安装列表。采用与试验结论集中在[实际接入验证](../evals/open-source-integration.md)，不在各处重复维护测试数字。

- **推荐局部适配：**问题选择、假说/批判性思考及完成复核方法；实际数值任务可优先评估适合的成熟后端、Optuna 与 Matplotlib。只采用适用模块，仍由原六步流程维护研究决定。
- **按需：**brainstorming、Docling、PaperQA、NEST/NEURON、BluePyOpt/eFEL、MLflow。是否采用取决于具体机制、数据、文献规模与团队记录需要，而非排名；Brian2 也不是所有任务的必选后端。
- **本轮暂不直接采用：**完整 Superpowers 自治实施流程、LangGraph 工作流层、整套科学 Skill 安装和重复的记录服务。前两者分别存在规则冲突、当前宿主能力已足够；未来实际缺口成立时可重新评估。

本页为注明来源的局部方法适配，未随附这些项目整套代码/技能文本。方法来源保留原许可信息；软件、权重、示例/数据的许可分别核对，不统一改标本仓库许可。专业工具迁移至新维护仓库后，原论文代码的旧版本仍按其真实身份保存，不悄悄用新库替换复现条件。
