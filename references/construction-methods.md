# 调研记录与模型构建方法

在研究模型的调研、方案确定、构建和交付时使用。核心产出是一份能据此实现并核对模型的构建方法，以及来源数值与实际参数之间的对应。用户仅要讨论时形成待选方法；已委托实施时按已明确的方案继续。明确指定复现对象、只做工程检查或只改 Skill 时，沿用该委托范围，不重新发起无关的建模研究。

用户只有现象或粗略想法时，先用[开放调研与追问](interview.md)形成当前可检验问题。先比较能改变决定的现象定义、条件和候选，再深读待采用分支；不要求用户提前提供全部科学问题、机制和参数。对既有模型的局部补充，按[机制接入](mechanism-extension.md)集中研究受影响部分。

检索前用已提供信息核对物种、解剖位置、脑区/细胞的中英文名称及适用图谱；同名、缩写和跨物种对应不能仅凭词面判断。例如小脑齿状核与海马齿状回属于不同对象。能从资料明确的事项直接核实，只有仍会改变研究范围的歧义才提问；名称与对象对应保存在当前方法，不另建名词清单。

涉及环境、疾病或干预时，按[场景调研](scenario-adaptation.md#先查发生什么再查为什么)先区分实际生物学变化与原因解释，再建立来源到模型的修改关系。把该依据纳入当前方法和最终报告；检索不能只找一个方便使用的参数倍率，也不要求原因已经完全确定才能比较候选。

## 保存实际调研过程

从第一次检索开始按时间追加记录，改变构建选择时保留原选择、改变原因及新选择。当前方法比较表和参数表可更新，关键旧版随实现归档。保存可以核实的操作、资料、结论与选择理由，不写冗长的内部思考过程，也不事后编造完整的检索历史。下面列的是内容归属，按[记录时机](project-layout.md#记录随工作推进)逐步建立，不要求首次调研就生成全部文件。

| 工程文件 | 应保存的内容 |
|---|---|
| `docs/research/search_log.md` | 按日期与要素记录研究问题、检索平台、实际检索式及筛选条件、查看的来源标识、可用性、纳入或排除理由、本轮发现、尚缺内容和下一步。结束时说明关键构建方法的覆盖情况与停止调研的原因。 |
| `docs/sources.md` | 为文献、公开代码、数据分别分配稳定标识，如 P01、C01、D01；记录题名、作者或提供者、年份、DOI/地址、版本或提交、访问日期和本地位置。说明原始研究、派生代码、移植与共享数据的关系。 |
| `docs/research/method_comparison.md` | 按构建要素对照不同研究的方法、原始数值、适用条件和实现差异，再写本模型选择、调整及不采用另一方法的理由。保留影响判断的相反结果和缺口。 |
| `docs/research/mechanisms/<mechanism_id>.md`，按需 | 用[机制说明模板](../assets/mechanism_plan.md)连接目标、论文/代码、状态与接口、参数适配和实际比较。小改动直接合并到当前构建方法；未选候选留在方法比较表，不每篇另建文件。 |
| `docs/research/parameter_mapping.csv` | 每个实际模型参数从来源到采用值的对应，字段要求见下节。简单模型可用同名 Markdown 表；整项任务选一种主要形式，避免重复维护。 |
| `docs/model_spec.md` | 将已选方法整合成完整、连贯的本模型构建说明；引用上述来源、比较及参数条目，实施后补入实际构建结果。 |
| `docs/element_coverage.csv`、`model/module_contracts.json` | 按[原清单落实规则](element-coverage.md)保留全部详细事项的决定和对应模块；每个启用模块给出七项定义，实施后登记源码、实际输出和检查位置。引用现有方法与参数，避免重复维护数值。 |

能合法获取且有必要保留的原文、补充材料、代码摘录及数据说明，集中放入 `docs/research/materials/` 并登记位置；实际计算所需数据放 `data/`。无法获取全文或代码时，记录实际可见范围，不能将摘要、搜索片段或仓库主页当成已核查的方法。不是每个网页都要下载，但关键来源必须有明确定位。已有历史工程缺少调研过程时，仅写能够恢复的记录及缺口，不反推虚构的检索日期或检索式。

数据来源还要注明数据集版本、动物或细胞等样本单位、筛选标准、实验协议、原始字段和单位、预处理步骤，以及用于构建约束、拟合还是独立检验。由数据统计出的参数应能定位到数据子集与计算方法，不只写一个下载地址。

数据用途在第一次读取响应和选模前确定，划分、已查看内容与评价次数按[数据用途规则](workflow-checks.md#数据用途在第一次使用时确定)登记，不能在看到结果后重标为独立检验。

### 让数据参与构建并明确缺口

按“要确定的模型量 → 哪种观测能约束它 → 数据如何转换/估计 → 不确定性与适用范围”组织数据工作，不能等模型完成才寻找一条相似曲线。区分直接测量统计、依据模型推导、通过仿真拟合与暂定假设；具体选择见[参数估计方法](run-compare-optimize.md#按数据和问题选择参数估计方法)。例如细胞密度与适用体积可用于推导数量，单细胞响应可约束部分细胞参数；仅有群体平均发放率并不自动确定每种离子通道或连接强度。

现有资料不足时，在方法的现有数据部分写具体需求，可直接用于向研究合作者说明所需记录，不笼统写“还需要更多数据”：

| 要确定的参数或待区分解释 | 需要的观测、条件与对照 | 数据格式/字段、单位、时间或空间分辨率、独立单位 | 能解决什么，不能解决什么 | 优先级、可用来源/替代方案与缺失影响 |
|---|---|---|---|---|

区分本轮必需记录和下一研究阶段有帮助的记录；采样长度、重复数量及精度按目标变化、已有变异与可行性提出建议，不套用固定样本数。把优先补充的一项数据和它能改变的决定联系起来。获取不到时保留已查结果及有限结论，不将待获取数据写成已用于估计，也不因填表向用户反复索要已有资料。

### 深读并比较多篇构建方法

新研究模型通常以 3–5 篇直接相关的原始建模或构建论文作为首轮精读范围，补充解剖、电生理等原始测量，核查多个相关公开实现。优先寻找假设不同的独立构建方法；同一模型的论文、作者仓库和移植分别登记，但只构成一个模型家族。研究问题很窄或可用资料有限时，写明覆盖范围与查找结果，不以无关论文补足数量。

这个范围用于完整新建研究，不作为每轮追问或局部机制接入的篇数指标。检索同时寻找有依据的替代解释、反例和勘误；每份资料记录其改变的选择。每轮得到影响选择的发现后，按[分轮交流](interview.md)集中提出 2–3 个相关问题并给建议，不等全部文献读完。关键选择已有依据、继续阅读主要重复、剩余差别需要模型或数据比较时转入已授权的首次构建；新结果继续触发定向补查与讨论。

阅读重点是方法、补充材料、参数表、数据处理及实际算法。逐项回答：研究者如何得到细胞模型和数量，怎样赋予位置，怎样选连接伙伴与突触位置，如何设权重、延迟和输入，怎样缩小规模或改用另一后端，如何检查生成的网络。与作者代码核对时追到实际使用的字段和函数；论文值与代码默认值不一致时分别保留并说明本次依据。

方法对照表按下列信息组织，可按要素分表：

| 构建要素与问题 | 研究和实现位置 | 原研究的方法与关键数值 | 适用条件与主要差异 | 本模型选择及具体改动 |
|---|---|---|---|---|
| 例如数量、三维布局、连接生成或突触动力学 | 来源标识、方法节/公式/表格；仓库版本、路径和函数 | 方程、抽样算法、分布、数值与单位；区分测量、拟合和作者假设 | 物种、脑区、制备、空间尺度、采样方式、模型表示及来源是否独立 | 采用、调整、组合或不采用的理由；指向构建步骤和参数条目 |

比较结束后形成一套可同时成立的方法。不能将一篇的细胞数、另一篇的密度和第三篇的连接概率拼在一起，却不检查体积、候选细胞集合与网络尺度是否相容。单篇论文没有覆盖的要素继续查对应原始资料；剩余未知量写为待估或假设，并说明影响哪些结果。

### 从候选方法选择本次构建路线

在现有 `method_comparison.md` 为确有实质差异的候选补充：能解释的目标现象、所需数据及可用性、与其他已选模块的相容性、计算/实现成本、关键假设与采用或放弃理由。不强制给不同科学目标的路线计算一个总分。

先确定主参考构建路线，再明确其他原始研究分别补充、校准或质疑哪些要素。主参考不能仅因代码容易运行而选定；逐项检查观测量、细胞表示、规模与输入协议是否适用。组合方法时把所需转换、参数依赖和仍不能解决的差异写清。

会改变路线的争议，在已授权预算内先做最小组件比较：使用同一可比协议、保存原始输出，比较目标响应、必要机制与代价。只调研时可交付具体比较方案，未执行的比较明确为计划。小比较只回答实际覆盖的问题，不当成网络实测验证。

结束选型时，方法说明能回答“为什么选它、替代路线差在哪里、哪些条件会使选择改变”，并明确首个实现及其检查。未知量标为假设或待估；不为凑足候选数量加入无关论文。

## 把来源数值对应到本模型参数

参数表以稳定的 `parameter_id` 标识本模型参数，覆盖实际配置中的科学参数和数值运行设置。数组或矩阵可以按有明确行列标签的一组参数登记；不能只对少数显眼数值标来源，其余默默采用默认值。多来源或多级推导可引用方法对照表、计算脚本及附表，避免把不一致的原始数值压成一个没有条件的均值。

需要自动核对时使用[CSV 表头](../assets/parameter_mapping.csv)及[自动检查说明](automatic-checks.md)，把表中数值与实际解析后的配置、网络导出数据比较。自动检查覆盖之外的推导和科学适用性仍需核查；主参数表保持一份，不能另写一套仅为通过检查的数值。

| 字段组 | 必需内容 |
|---|---|
| 参数对象 | 参数标识、要素编号、所属细胞群/投射/突触/协议、变量定义及矩阵方向。 |
| 原始来源 | 来源标识、公式/表格/图/补充材料或代码版本与字段；原始变量名、数值或范围、单位、分布、样本与适用条件。来自实测数据时写明数据子集和估计方法。 |
| 转换过程 | 直接采用、单位换算、模型转换、按规模推导、数据估计、拟合或建模假设；写公式、代入值、必要中间量及舍入规则。非平凡转换给出可执行函数或可复算计算。 |
| 本模型采用值 | 实际值、范围或分布与单位；分布写明参数含义、截断和采样方式，不能用均值冒充全部个体的取值。可调参数写初值、允许范围和拟合后的值。 |
| 选择理由与边界 | 为什么适用于本模型，跨物种、温度、制备或尺度的变化依据是什么；记录替代值、不确定性与待检验之处。没有直接来源时明确写假设或数值设置及选择理由。 |
| 落实位置与核对 | 配置键、代码文件与函数/机制、实际运行配置或生成表的位置，以及计划采用、已实现、已从输出核对的状态。临时覆盖配置和参数更新同步登记。 |

特别核对以下转换：

- **数量与尺度。** 数量来自密度与体积时写出计算和单位，分群写比例分母、缩放与取整方法。缩小网络时说明保留的是密度、入度、连接概率、总输入等哪些量，哪些会改变；不能默认同时保持所有性质。检查取整后稀少群体、必要投射和可用来源数是否仍足以实现方案；不为保留名字暗增细胞或强加连接，需在方法中说明调整、最小规模或该规模的能力限制。
- **三维坐标。** 写明坐标原点、轴向、左右手约定、单位及解剖层次；由图谱或重建数据变换时保存转换关系。毫米到微米的换算与坐标系转换分别记录。随机生成的位置标为生成值，不写成实测解剖坐标。
- **连接数量。** 概率、每目标不同来源数、每对接触数与总接触数分别定义，写候选集合、方向、自连和重复规则。由一种表示换成另一种时使用适用的抽样模型，不凭名称相近直接替换。
- **突触强度。** 突触后电位幅度、峰值电流、峰值电导和后端权重不是通用的同一种量。转换必须依赖实际细胞方程、突触波形、单位及所需膜参数；条件不全时保留待估，不只换标签。单接触强度与一对细胞的总作用也要区分。
- **拟合更新。** 保留文献或数据给出的初始依据、拟合使用的数据与目标、参数范围和最终值。拟合值标为估计结果，不改写成文献原值，也不把拟合数据重新当作独立检验。
- **机制适配。** 连同方程、输入初态和共同标定的参数组核对数值。总量/密度、游离/总浓度、有效状态/生理量分别说明；涉及面积、体积、温度、共享状态或数量缩放时保留相应转换。固定参数改成动态状态时同步更新依赖项，具体见[参数和状态适配](mechanism-extension.md#参数和状态一起适配)。

例如来源写 `0.020 s`，采用 `20 ms`，应记录乘以 1000 的换算；若体积和密度经过缩放，写出每一步后才能得到各群体整数数量。这类算例仅说明记录方式，不提供默认生理参数。

## 把比较结果整理成构建方法

正式构建前在 `docs/model_spec.md` 完成下面内容。它是一份具体的方法说明，不能只写“建立神经元、连接网络、运行仿真”。按[原清单的全部详细事项](element-coverage.md)检查覆盖，每项明确所选方法、参数条目、简化和适用范围；下表是方法叙述的组织方式，不替代原清单的逐项检查。

| 方法部分 | 必须明确的构建内容 |
|---|---|
| 目标与设计 | 要解释或预测的现象、研究对象、时空尺度、条件与对照、观测量、检验方式和本轮预算；哪些结构是回答该问题必需的。 |
| 细胞模型 | 每类细胞的表示、具体方程或机制版本、状态与单位、阈值/复位/不应期或离子通道、区室与温度处理；说明为何选该模型及其能力边界。 |
| 群体与数量 | 群体身份、脑区/层次、原始数量或密度、体积、比例、规模缩减、取整、个体差异和最终各群体数量。外部事件源单列，不冒充动态神经元。 |
| 三维布局与形态 | 建模体积与边界、坐标系和单位、各层范围、空间采样或重建方法、必要的排斥距离、随机设置、形态/区室与取向。点神经元的电学简化不意味着没有空间位置。若采用非空间模型，明确不建模的位置量及其影响；用于展示的布局不能作为解剖或距离连接的依据。 |
| 逐条投射 | 来源群 → 目标群、连接方向、概率/固定入度/总接触数等生成规则、距离或细胞特征依赖、候选集合、自连、多接触、边界处理、伙伴选择顺序及随机设置。不能仅给一张没有行列含义的矩阵。 |
| 突触与耦合 | 各投射的受体或机制、作用位置、每对接触数、权重与分布、反转电位、上升与衰减时程、延迟及其计算、可塑性状态与更新；记录各参数的方程和后端含义。 |
| 输入、初值与运行 | 背景及刺激来源、相关性、目标、波形与时段；初始状态、预运行、条件之间共享或重置的状态；后端、步长、事件顺序、种子、独立重复和预算。 |
| 记录与分析 | 保存哪些细胞、输入、状态和时间点，是否覆盖全部细胞或抽样；实验信号映射、指标、样本层级、误差、检验标准，以及拟合与留出划分。预先确定应保存的数据与图件。 |

另列一张**构建步骤表**，每步写“输入及来源/参数条目 → 实际算法与调用位置 → 输出及单位 → 检查方法”。典型次序是：读取并检查参数，确定群体与数量，生成细胞和位置，生成连接伙伴及接触，赋予突触机制/权重/延迟，配置输入与初值，设置求解与记录，运行并导出，最后分析绘图。依后端调整次序，但依赖关系、状态归属和随机抽样顺序必须明确。

每步完成时保存实际产物及检查，结果报告沿相同步骤展示输入、产物、检查和下一步用途，见[每步构建结果](result-delivery.md#以构建步骤的实际结果为主线)。方法表中的“计划输出”与已产生的结果状态分开，不以流程示意图代替实际记录。

目标与关键流程确定后，必需参数应具有可执行的值、分布或生成规则。资料不充分时可在已委托范围内采用明确的探索假设，并说明如何检验；会改变科学目标的选择再向研究者提问。实施改变数量、坐标规则、连接语义或参数时，更新方法与版本，不能在代码里悄悄改动。

构建方法同时采用[分阶段检查与调整规则](workflow-checks.md)，把启用的结构与目标观测量对应，并为各阶段规定检查、完成条件及失败后的动作。已写明的内容直接引用，不在多个文件重复维护。

## 保存并检查实际构建结果

对逐细胞网络，从实际生成的对象导出下列内容到 `results/<run_id>/raw/`，使用 CSV、NPZ、HDF5 等合适格式；大网络可用稀疏或分块存储，不为了统一格式额外复制数据。

- **细胞表。** 包含稳定的 `cell_id`、群体、细胞模型/机制标识，适用时的形态标识、`x/y/z` 坐标与单位和个体参数。坐标系、位置来源及生成方法写在配套元数据中。未建模的坐标明确为不适用，不用全零伪装实际位置。
- **连接与突触表。** 包含来源与目标细胞、投射或突触类型、每对接触关系、实际权重及单位、延迟，适用时的区室/位置和可塑性初值。合并表示多个接触时保存接触数和等效规则；汇总概率矩阵不能代替实际边或接触记录。
- **输入、状态与观测。** 保存实际送达的输入、种子或必要的事件序列、初始状态、所需尖峰/电压/电流等原始量、时间及单位、记录细胞与条件标识。模型原始量和从它推算的实验信号分开。隐式或程序化连接须保存足以恢复实际连接的规则、参数、随机状态与实现环境，并用恢复后的连接核对，不能只留配置中的期望值。

按实际表核对各群体数量和唯一标识、空间范围与分层、投射方向、自连和重复、伙伴与接触数、权重/延迟分布、输入目标和时间。随机生成的分布按预定统计量与容差比较，不要求每次抽样恰好等于理论概率。核对摘要写入 `run.json` 的构建结果部分，当前构建方法引用对应运行与原始表，避免另建重复报告。计划内容、实际实现和实测检验分开标明。

多脑区或多群体模型还要从实际连接统计来源群 → 目标群的不同细胞对数、接触数及覆盖情况，核对必要通路和输出接收端。表中有脑区名称或配置概率不表示实际存在跨区连接。小规模随机抽样的零连接先判断是否符合抽样规则，再判断是否仍能研究目标通路；两者不能混为一项“通过”。如需条件抽样或更大规模，记录改变的规则及理由。

### 输入与实验协议也要检查

在正式运行和根据偏差调参之前，沿“原始记录/生成协议 → 预处理与单位、时间转换 → 实际送达模型的量”核对；结果放在已有输入步骤及运行摘要，原始数据、转换代码和送达记录互相引用。设计值不能代替送达检查，目标刺激也不能与背景输入混合统计后掩盖异常。

| 适用输入 | 检查内容 | 对后续判断的影响 |
|---|---|---|
| 所有输入和协议 | 对象标识、单位、时钟起点、时间单调性、缺失/重复、插值/重采样、有效覆盖、目标对象与实际应用时刻。 | 不匹配先修正输入或协议，不能用模型参数补偿错位、缺失或单位错误。 |
| 行为、轨迹或空间采样 | 真实数据还是生成值、坐标转换、速度、停留时间、访问范围、占据时间及不均匀采样；检查与任务有关的宽度/边界。 | 未访问位置不当作零响应；采样偏好和空间响应分别分析。只在相关任务启用，不给一般静息网络增加轨迹。 |
| 刺激、事件源与回放 | 计划与实际事件数/时刻/目标、传导或读取延迟、截断及队列；连续输入核对幅度/波形/积分等适用量。 | 输入事件、突触送达和神经元输出分开记录；事件数或预设率不能冒充网络实际发放。 |
| 多阶段或连续条件 | 准备、刺激/暴露、撤除、观察的时间关系，状态继承/重置，比较条件的观察长度和历史。 | 对照不匹配或连续性错误先处理；缺少状态时不能把不同独立片段当作连续过程。 |

输入可以是符合研究设计的随机或合成序列，按生成规则与统计标准检查；不要求与单次实验逐点一致，也不为让输出图好看而修改有效输入。输入本身参与估计时，把可调整量、依据及数据用途列入同一参数表。

## 结果数据和结果图一起保留

正式交付包含 `results/` 中支持结论的原始记录，以及 `analysis/output/tables/` 的分析数据、`analysis/output/figures/` 的正式图件和生成它们的分析代码。当前正式表格与图件是交付内容，不能因“可以重新生成”而全部清除，也不能只保存截图而丢掉数据。

在分析记录中为每张正式图登记图文件、输入表及所用字段/筛选条件、原始 `run_id`、分析设置与绘图入口。数据共享一份即可，不为每张图复制同一批原始数据。记录分组、重复单位、样本量、平均或归一化、误差条的定义，使图上的量能从保存的表重算。至少实际重生成主要结果图并核对数据、轴单位与条件；其余图检查对应关系。

同时保留用于理解构建的细胞数量、空间或投射统计；需要构建图时用实际细胞与连接生成，若抽样显示则注明规则。方法示意图与实际网络结构图应明确区分。最终结果的保存要求与[工程整理规则](project-layout.md)一致：只保留一套当前实现和当前分析，调研记录、必要的原始数据及正式图件随交付保留。

最终内容按[结果交付](result-delivery.md)组织为每步构建产物、活动、主要对照比较和可信范围。用同一份分析记录维护数据字典、步骤及图件对应；先定记录范围，保存逐独立单位指标，区分缺失原因，并从数据重算主要图表。
