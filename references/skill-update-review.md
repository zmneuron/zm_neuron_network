# 每次调用的上游更新与技能冲突检查

检查对象是[来源清单](external-skills/sources.json)登记的 ARS、anti-defensive-writing 和 Ponytail，以及本次实际采用的其他外部技能、计算软件和科学代码/数据。**每次明确调用或在新任务中重新进入本技能都检查一次**，不是每次搜索、每条消息或每个建模阶段都重查。同一次调用已完成且采用版本不变时复用记录；中途换技能版本时补查受影响部分。下面的查询脚本只覆盖原有三个随附来源；新增接入按[阶段性复用的更新规则](open-source-reuse.md#更新恢复和数值使用)查询官方来源并写入当前采用记录，不能将该脚本通过说成所有软件均已核实。

用户明确要求不联网时，只核对本地材料，记录上游状态“按本次要求未查询”，不运行会联网的命令；不把这次本地检查写成已核实上游最新版本。

## 先检查版本，再检查实际规则

1. 恢复用户目标、当前科学决定和任务范围。读取[技能分工](skill-integrations.md)，列出本轮实际参与的模块及来源；默认使用随附版本。其他项目同名 `deep-research` 不能视为 ARS，也不能凭文件夹名称认定版本相同。
2. 运行下面的只读查询工具。它每次访问三个上游仓库的当前默认分支，比较本技能实际采用的上游文件及许可证，核对随附原文/适配文本是否与来源清单一致。只发送公开仓库及版本信息，不发送研究数据，不下载执行插件，不覆盖技能或模型文件。

```text
python -B -X utf8 <skill目录>/scripts/check_skill_sources.py --active zm_neuron_network --active ars:deep-research --output <研究工程>/docs/research/skill_checks/<本次时间>.json
```

`--active` 可重复，例如加入 `ars:academic-paper`、`ars:academic-paper-reviewer`、`anti-defensive-writing` 或 `ponytail`。从任意工作目录可运行；`<...>` 是需替换的路径/时间。没有工程或任务只允许读取时省略 `--output`，结果输出到当前会话。记录保存在研究工程，不能写回共享技能目录；同名记录不覆盖。

3. 解释查询状态：`unchanged` 表示上游提交与采用版本相同；`repository_updated` 表示仓库变化，但登记采用的文件未变；`update_available` 表示相关文本或许可发生变化；`unverified` 表示请求失败、限流或资料不完整。随附文件不一致另报 `local_integrity=failed`。上述状态均**不等于语义上无冲突**。
4. 仓库有变化时先查看提交或发布摘要；有相关更新时打开固定的新旧版本，阅读差异及变化条款实际依赖的参考文件。核对任务范围、提问方式、数据真实性、参数/指标、文件改动、网络与工具调用、运行环境和许可；上游新增的行为不能直接当作本次用户授权。未涉及采用模块的仓库变化无需通读整个项目，但应留意影响接入方式的新功能。
5. 每次结合下面的已知冲突表，检查实际采用文本与本技能以及彼此的关系。无版本变化仍核对本次任务是否触发这些冲突；采用新版本时重新检查受影响规则。其他已安装技能若实际参与，也登记其来源、版本、作用和冲突处理，无法核实的不要写“已检查”。

## 已知冲突与本项目处理

这是适配规则和检查提示，不是永远有效的“无冲突证明”。新版本可能增加新冲突。

| 相关技能/规则 | 冲突或重叠 | 本项目采用方式 |
|---|---|---|
| ARS 的纯 Socratic 模式与本技能 | 原模式默认不生成候选、不直接给答案；本方向要求先查资料，再给建议与影响 | 不默认启用该纯模式；按已选建模档位逐阶段调研和分批讨论，题数与收束遵循 [interview.md](interview.md)。构建讨论之外另加科学讨论；完成后开放式优化重新研究并询问，旧结束状态不阻止新讨论，已有答案不重复问。 |
| ARS 总流程与本技能 | 上游逐阶段要求确认；本技能已委托实施后需持续完成 | 保留领域调研、科学设计和结果解释的讨论，不引入机械的“下一步是否继续”。新范围和必要决定仍按用户要求确认。 |
| ARS、anti-defensive-writing 与真实结果 | 审阅要求核实局限和反向结果，表达技能强调贡献与优势 | 真实数据、完整结果和适用边界优先；优化叙述，不能删掉影响判断的阴性结果、对照或失败记录。 |
| ARS 写作与 anti-defensive-writing | 可能分别重排结构、引用及论点 | ARS 适配负责问题—方法—结果关系，表达技能修改同一份文本；改后逐条核对数据、引用、摘要及图表。 |
| Ponytail 与完整建模 | 软件简化可能与必需机制、模块分工、运行与保存要求冲突 | 最小完整实现，保留目标依赖机制、14 类构建要求、独立分析、真实运行和结果；模型约化需科学依据。 |
| ARS 审阅/写作与建模实验 | 为满足审阅、叙事或格式而改数据用途和评价标准 | 先明确补充请求，确需计算就返回建模；保持原主要指标和数据用途，新增探索另行说明。 |
| 多个总流程、安装版与随附版 | 路由重复、不同当前文档或同名不同来源 | 当前主助手只维护一个科研流程和一份当前状态；采用版本明确，不同时运行两套控制流程，不凭同名替换。 |
| 上游插件与当前宿主 | 专用命令、代理团队、外部模型/上传、钩子可能不可用或未授权 | 按当前工具和授权运行适配流程；未实际执行的独立审阅、引用脚本或跨模型检查不能宣称已完成。不自动安装插件或执行下载脚本。 |
| 不同输出格式与许可 | APA/语言/论文声明与当前模型报告不匹配；ARS 非商业许可不同于 MIT | 跟随本轮语言、期刊与产物要求，不虚构声明；保留每个来源许可及修改说明，不统一改标 MIT。 |

用户明确要求和上层运行规则优先；本技能的科学完整性、实际运行和诚实报告要求不因辅助技能改变。能够按本页消解的已知冲突直接处理并记录，不再请求许可。仍会改变科学解释或用户目标的冲突，提出具体取舍问题，继续不依赖该决定的工作。

## 检查、采用与更新是三个状态

- **检查结果：**脚本只核对来源版本和本地文件一致性，输出的 `semantic_review.status` 固定为 `required`。它不会自动判断规则兼容，更不会把上游最新提交标记为已采用。
- **采用决定：**助手完成上述阅读后，在同一报告的 `semantic_review` 中填写实际作用范围、检查过的规则组合、发现项、处理理由、最终读取版本和未完成项。可用状态为 `completed`、`partial` 或 `blocked_for_affected_work`；只有已检查项可写已解决。`completed` 不表示绝对不存在未知冲突。
- **保持研究一致：**默认使用已核对的随附版本完成本次研究。相关更新经检查适用后，可在允许的维护范围中采用，并同步原文/适配、来源版本、许可、引用与必要测试；不能只改版本号。在普通建模调用中不直接覆盖共享技能或全局安装，候选更新与采用建议记入报告。
- **无法联网：**优先通过可用的 GitHub 工具或浏览访问上游复核，填入真实检查方式；仍无法获取时记录 `unverified`，使用本地完整且已核对版本推进可行工作。若新功能必需而旧版缺失，只暂停依赖它的部分。禁止用旧缓存写“刚刚检查过”。
- **本地文件变化：**有意的适配修改也需与清单对应，查清后更新采用记录；来源不明时先恢复或选用已知版本，不能忽略一致性失败。仅凭发布日期更近或星数更多不能决定升级。

一份调用记录包含检查时间、上游/随附版本、相关变化、实际采用的技能、冲突处理和剩余问题。`docs/progress.md` 只链接最新记录并简述对当前研究的影响，历史保留在同一 `skill_checks/` 目录。只谈论技能或只读审查时，可在会话中报告这些内容，不向科研工程写文件。

脚本返回码：`0` 表示版本查询和本地一致性检查完成（仍可能有更新，语义检查仍待做），`2` 表示有未核实或本地不一致项，`1` 表示输入/输出错误。它不证明模型正确，也不替代文献和数据核查。
