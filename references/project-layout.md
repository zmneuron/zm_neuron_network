# 工程结构与最终交付规则

适用于新建模型的方案、实现和最终整理，也适用于用户明确委托的既有工程整理。只要求检查、讨论或改进 Skill 时，只读指定样本。目录名默认用稳定的英文，说明用中文；用户已有明确命名约定时沿用。

## 记录随工作推进

目录示例展示完整工程，不能据此在开始调研时一次生成全部空文件。由实际产物决定创建时机；已有内容放在同一职责位置，其他表只引用标识或章节。

| 何时有实际内容 | 主要保存位置 | 避免重复的方式 |
|---|---|---|
| 理解问题与分轮讨论 | `docs/progress.md` 或已有同职责主记录 | 保存当前目标、决定、待讨论点和下一动作；不另建问卷、访谈纪要和多份当前状态。 |
| 检索来源并比较方法 | `docs/research/search_log.md`、`docs/sources.md`、`method_comparison.md` | 分别保存真实检索、来源身份、方法取舍；小规模研究可先在同一文档分节，正式交付保留必要内容。 |
| 候选机制与参数开始确定 | 当前 `model_spec.md`、一份主参数对应表；独立适配确有需要时使用机制说明 | 机制卡和方案引用主参数表；候选淘汰前不抄全部参数、不开独立网络工程。 |
| 为选型实际做小比较 | 简短方法/运行说明、实际代码与配置、原始输出及分析 | 保留命令、环境、随机设置与输入。只证明该小比较，不强制先造全部结构化记录。 |
| 完整方案与正式构建 | `element_coverage.csv`、`module_contracts.json`、`task_plan.json` | 逐项表管要素处理，模块表管实现，任务表只关联本轮要求；科学理由、参数数值不在三处各维护一遍。 |
| 运行、分析与交付 | `results/<run_id>/`、`analysis/output/`、`docs/results.md` | 原始记录只保存一份，分析引用它；输出索引提供位置与对应，报告解释结果，不另造最终结果工程。 |

记录深度见[探索与正式构建](workflow-checks.md#探索小运行与正式构建)。为完整交付保留所有必要信息，但不把创建文件数或填写次数当成研究进度。

## 默认目录及职责

下列是包含细胞、突触与连接的网络示例，文件名随后端调整。只创建实际使用的部分，Python 包初始化文件等必要文件按实现补齐。

```text
<project>/
├── README.md                  # 当前状态、目录导航、安装和运行命令
├── requirements.txt           # 或该后端的一份主要依赖声明
├── model/                     # 当前唯一一套模型构建源码
│   ├── run.py                 # 仿真入口：读取配置、组装、运行和保存
│   ├── module_contracts.json   # 启用模块七项定义及源码、输出、检查位置
│   ├── config/
│   │   ├── model.json         # 细胞、连接、突触、输入和运行参数
│   │   └── load.py            # 配置读取、单位及范围检查
│   ├── cells/
│   │   ├── populations.py    # 群体、细胞身份、数量及个体差异
│   │   └── dynamics.py       # 单细胞状态、方程及初始化
│   ├── network/
│   │   ├── geometry.py       # 按需：空间范围、三维位置与坐标转换
│   │   ├── connectivity.py   # 有向投射、伙伴选择及连接表
│   │   └── build.py          # 将细胞、连接和突触组装成网络
│   ├── synapses/
│   │   └── mechanisms.py    # 受体、权重、延迟和按需可塑性
│   ├── inputs/
│   │   └── protocols.py     # 背景、刺激和配对对照
│   └── simulation/
│       ├── solver.py         # 数值推进、事件调度及运行状态
│       └── recording.py      # 原始变量、连接和输入的保存接口
├── analysis/
│   ├── run.py                 # 从指定原始记录重新计算的入口
│   ├── config.json            # 指标、时窗、统计与图形参数
│   ├── metrics.py             # 指标与条件比较
│   ├── plots.py               # 绘图
│   └── output/
│       ├── tables/            # 指标、条件比较及图件使用的数据
│       ├── figures/           # 当前正式结果图
│       └── analysis.json      # 构建步骤产物、科学结果、数据与图件的对应
├── results/
│   ├── index.json             # 当前交付采用的仿真与分析记录
│   └── <run_id>/
│       ├── run.json           # 实际命令、版本、环境、种子及状态
│       ├── config_used.json   # 运行时的实际参数，包含临时覆盖值
│       └── raw/               # 实际细胞/坐标、连接/突触、输入和轨迹
├── docs/
│   ├── model_spec.md          # 完整当前构建方法：目标、流程、参数与核对
│   ├── task_plan.json          # 本轮要求与要素、模块、参数、步骤和结果的关联
│   ├── element_coverage.csv    # 原清单全部详细事项的决定、模块和检查状态
│   ├── sources.md             # 文献、代码、数据的来源目录及稳定标识
│   ├── research/
│   │   ├── search_log.md      # 实际检索、筛选与补查记录
│   │   ├── method_comparison.md  # 多来源构建方法比较与采用理由
│   │   ├── parameter_mapping.csv # 来源原值、转换、本模型值及实现位置
│   │   └── figure_plan.md      # 文献图阅读与本模型面板设计，可补入已有记录
│   ├── results.md             # 构建流程每步结果、科学比较、检查及适用范围
│   └── progress.md            # 当前状态、未决问题、累计预算和下一步
├── data/                      # 按需：外部实验输入及预处理数据
└── tests/                     # 按需：与本轮结论有关的实现检查
```

小工程可合并说明文件，例如把进度写入当前方案、把结果说明写入 README；调研过程、构建方法与参数对应的必要内容仍应保留。逐项表与模块索引用于[核对原清单](element-coverage.md)，引用同一份方法、参数和结果，不另抄一套数值。资料下载量较大时，在 `docs/research/materials/` 统一保存需要保留的原文、代码摘录及数据说明并登记来源，下载失败的响应和网页缓存不作为正式资料。引用外部代码时保留许可证和版本。用于实际运行的形态与机制文件放到对应模块的资源目录，不能只藏在调研下载目录或历史工程里。构建说明、调研记录及实际网络数据的字段见[调研与构建规范](construction-methods.md)。

`data/` 存放外部输入，`results/` 存放模型生成的原始输出，`analysis/output/` 存放可以从它们重算的派生结果。三者职责分开。多个实验协议、条件、种子与重复是同一版本模型的研究内容，可按明确的标识分目录；它们不属于待清理的旧版本。

按问题扩展机制时，小改动并入 `model_spec.md`；需要独立适配说明才建立 `docs/research/mechanisms/<mechanism_id>.md`，由主方案引用。代码仍按细胞、突触、局部环境及求解的实际职责归属，不为每篇参考论文复制一个网络工程。已选机制说明引用既有来源、参数和结果，未选候选保留在方法比较表。

`progress.md` 或已有同类主记录统一承接当前问题、依据/假设/决定、有效版本、结果及下一动作，字段见[续接规则](interview.md#一份当前状态接续研究)。调研、提问和局部构建不是各自再创建一份“当前状态”。

## 按神经网络组成拆代码

| 要素 | 默认实现位置与边界 |
|---|---|
| 01–02 研究问题、物种与条件 | 在 `docs/model_spec.md` 说明；实际影响运行的温度、条件等同时写入配置。 |
| 03–05 群体、空间与细胞动力学 | 细胞身份与方程放 `model/cells/`；全网络空间布局放 `model/network/`。需要多区室时在细胞模块内增加形态及离子机制文件。 |
| 06 参数与单位 | `model/config/` 管理可调整参数与读取检查；推导公式放其所属细胞或突触模块。相同参数只维护一处，实际运行副本只作记录。 |
| 07 连接结构 | `model/network/` 定义来源与目标、连接生成及组装；与突触作用强度的计算分开。 |
| 08 突触与可塑性 | `model/synapses/` 定义电流或电导、状态、时间常数、延迟和更新。 |
| 09 外部输入 | `model/inputs/` 生成或读取背景及刺激，明确目标、单位、时间和随机来源。 |
| 10 额外生理机制 | 按科学职责放入相关模块或新增实际需要的模块，不建空的通用机制框架。 |
| 11–12 初始状态与求解 | 细胞、突触定义各自状态；`model/simulation/` 调度初始化、事件、随机过程和求解。 |
| 13 记录与实验信号 | `model/simulation/recording.py` 保存原始变量；仅用于观测的信号映射放 `analysis/`，若反馈影响动力学则属于模型模块。 |
| 14 指标与比较 | `analysis/` 管理指标、统计、校准评价和图形，读取实际配置及原始输出。 |

同一细胞方程只因参数不同而区分亚型时，共用实现，用配置表达群体差异；不要按 E、PV、SOM、VIP 等名称复制整段代码。只有方程、形态或机制实质不同，才拆独立实现。

各模块的实际计算应与名称相符。不能新增几个转发文件，却把全部工作仍放在 `model.py`、`core.py` 或 `utils.py`。运行入口不定义所有生物机制，模型构建不导入绘图或分析入口，分析不依赖 `run.py` 的内部函数。公共数据格式确有复用时提取到独立的小模块，避免循环依赖。若后端要求编译连续的积分循环，可在求解器中保留该循环，但细胞参数构造、连接生成、输入生成和分析仍各自独立；记录方程所属模块与求解位置。

这些职责也适用于 NEURON、NEST、Brian 或其他后端，不要求为拆目录改用新的后端。单细胞任务只建立所需的细胞、输入、求解和分析模块，不虚构网络或突触文件。文件数量由实际职责决定。

## 当前版本、运行记录与历史

**当前交付根目录就是最终模型工程。** 不再并列复制 `final/`、`latest/`、`model_v2/`、`final_final/` 等整套实现。版本写在方案和运行记录中；当前代码、配置、入口和说明使用稳定路径。`docs/model_spec.md` 必须独立表达当前模型，不能仅写“继承 v1，再修改以下两项”。

- 每次实际仿真使用独立 `run_id`，先写入工作输出位置；运行完成且必要检查通过后，再登记到 `results/index.json`。索引列明当前使用的运行目录、对应分析记录及检查状态，不按修改时间或最大的版本号自动选取。必要检查指本轮约定的实现和数值检查，实测验证是否完成另行注明。
- 一次运行可包含全部匹配条件和随机重复，也可由多个运行共同支持一组结果。索引应覆盖完整集合。不能因“只留最终模型”删掉对照、独立随机重复、拟合与留出数据，或隐藏影响解释的失败结果。
- 每个运行保留实际配置、命令、环境及可恢复的实现标识，**不要在每个运行目录里复制整套源码和方案**。已有版本管理可引用完整提交；未提交修改或未纳入版本管理的运行文件必须另外保存，不能只记录一个与实际运行不符的提交号。没有版本管理时，每个实现版本仅归档一次必要的源码、配置与依赖说明，各次运行引用它。校验值只能检查一致性，不能代替可恢复的源码。
- 历史默认保存在版本管理中或交付目录之外的一处归档，并记录位置。只允许在工程内部保存时，集中到 `archive/` 并明确排除在最终交付集合之外。归档限于该工程必要文件，避免递归复制整个父目录、外部环境或多份相同记录。历史归档是保留方式，不是当前工程的运行依赖。
- 每轮交付整理过期方案、旧分析、试跑、缓存及临时预览。调研过程记录、方法比较、参数转换与采用依据属于当前交付，不能当作临时过程稿移除。仍需保留的旧实现或旧分析移到归档；可再生成且与结论无关的缓存可从交付中排除。旧源码或研究记录在确认已可恢复之前不作不可逆删除。用户另有删除或保留要求时按其范围执行。
- 新版本未完成或检查失败时，不覆盖已通过检查的当前版本；在进度中写明最新尝试和问题。确需交付未完成模型时明确标注状态，不将“最新版”写成“已验证”。整理不能通过挑选成功的条件改变研究结论。

版本含义和最小运行记录见[版本与一致性规则](versioning.md)。

## 重分析与图形更新

1. 分析入口接受已有运行目录或数据标识，读取该次运行的实际配置；分析设置单独保存。不能用今天的模型默认值冒充历史运行参数。
2. 只改指标、时窗或绘图时，复用同一批原始记录，仅生成新的表格、图形与分析记录。若所需原始变量未保存，说明无法直接重算的原因，再按任务预算补算需要的仿真。
3. 分析记录写明原始 `run_id`、数据位置、分析代码与配置、实际命令及版本。原仿真的命令、模型版本和状态保持不变；分析时间与耗时独立记录。拟合数据用途与留出评价次数也随原记录保留。
4. 旧分析有必要保留时单独归档，新分析通过检查后替换当前 `analysis/output/`，并更新结果索引与说明。工作目录暂存和最终发布分开，不能在计算到一半时覆盖已交付图表。
5. 图形只保留实际使用的格式，通常为一种可编辑矢量格式及按需位图预览。表格保留一种主要数据格式；不同格式各有用途时可并存并说明对应关系。临时截图和重复预览不混入正式图件。
6. 当前正式数据表和结果图必须随工程保存。在 `analysis.json` 中写明每张图使用的数据表、字段/筛选、原始运行及分析设置；绘图代码读取这些保存的数据，不手工拼接无数据依据的曲线。详细要求见[结果数据与图件](construction-methods.md#结果数据和结果图一起保留)。
7. 结果报告沿实际构建顺序呈现每步产物和检查，再呈现主要科学比较；适用内容与具体表图见[结果交付](result-delivery.md)。每步通过标识引用已有文件，不为输出流程额外复制原始数据或整套源码。

## 交付前检查

在本轮授权范围内完成，检查失败先修复引用或实现，不继续清除旧文件。

- **内容完整。** 当前构建方法能独立阅读，目标、流程、参数及各步输出明确；调研过程与多来源比较已保存。[原清单逐项表](element-coverage.md)无漏项，启用模块均有七项定义、实际实现和检查结果；配置、代码位置、文档链接及结果索引与最终目录一致。必需模块缺失、未接入或尚未核对时不能宣布完整交付。当前结果所对应的模型和分析版本可明确辨认。
- **来源与实际模型对应。** 关键数值能由参数对应表复算，配置中的科学参数有来源或明确假设。细胞数量、适用时的三维坐标、实际连接与突触参数已保存，并与方法说明核对；不能只检查配置声明。
- **检查范围清楚。** 按[分阶段规则](workflow-checks.md)记录适用的组件、网络和数值检查，区分未完成与不适用。使用[自动工具](automatic-checks.md)时保留实际范围与尚待人工核查项；关键假设的比较按本轮目标与预算完成。
- **可以运行。** 在最终目录从 README 指定的工作目录执行一次小规模模型运行，再由分析入口读取其输出。检查输出写入指定位置，关键量符合约定，不混入正式结果。若模型可从任意工作目录启动，另核对路径解析；不要依赖个人绝对路径、临时工作区、历史归档或原先的目录布局。
- **整理未改变模型。** 只移动或拆分代码时，保持原输入、种子策略、单位、细胞与边顺序、初始化和求解设置，用同一小组输入比较离散连接、事件和关键连续量。容差按方案执行；只改分析时核对原始文件未被改写及新指标符合定义，不重跑全部实验。
- **重分析可独立执行。** 重算主要指标并重新生成主要结果图，确认不调用仿真、不复制原始记录，原仿真记录未被改写。当前正式数据表与图件均已保留，每张图能定位到真实使用的数据、单位和条件。
- **结果覆盖且可理解。** 每个必需构建步骤有实际输入、输出、检查及后续用途；主要问题有逐独立单位结果、匹配对照和适用的效应量说明。字段/轴/单位齐全，计划条件与重复未遗漏，空值有具体原因。按[输出检查](result-delivery.md#可执行的交付检查)检查记录，另核对二进制内容与图形显示，不能以文件存在代替科学正确。
- **交付简洁。** 当前源码只有一套，研究内容与历史文件已分开；缓存、虚拟环境、临时预览和失效下载不计入交付。确认当前模型及分析读取的必要文件都仍可获得后，才移出历史副本。

README 让使用者能直接找到：构建方法及调研记录、来源到模型的参数对应、如何安装、如何运行模型、如何重新分析、在哪里改参数、结果数据与图件、哪些预测尚无实测检验。续接信息只保留一个当前记录。一般不另建重复的交付清单、完成报告和多份进度文档。
