# 多 agent 按职责动态编组

在独立调研、可分离的实现或重要研究交付的复核有实际价值时使用；不增加另一套科研流程，也不要求固定人数。先核对当前宿主是否提供子 agent、实际并发上限、权限和共享文件方式，再决定分工。这里的 agent 是 AI 工作角色；候选仿真的并行计算另行调度，二者不是同一种资源。

## 三类职责与共同状态

| 职责 | 承担的工作 | 责任边界 |
|---|---|---|
| 主 agent | 维护原要求、科学问题、适用规则、采用版本、指标、数据用途和累计预算；安排依赖、用户沟通、整合、最终完成判断与发布 | 独占当前计划和采用决定。工作 agent 的建议不自动成为用户决定，不依据它们的自评宣布完成。 |
| 研究/实现工作 agent | 按实际缺口组合需求与科学问题研究、方法/数据/参数调查、模块实现、允许的运行、校准或分析 | 只修改指定文件或隔离工程。提交来源位置、实际动作和产物、可复算结果、未解决项及成本，不自行改科学目标、数据用途或发布。 |
| 独立复核 agent | 从原要求和实际代码、配置、原始数据、图文检查关键关系，复算影响结论的量 | 尽量由未承担相应实现的 agent 负责。默认只读实现，写独立意见或复算结果；先看原材料，再看实现者说明，不能只复述自评。 |

科学问题、方法参数、实现运行、校准分析、交付复核是可组合的职责，不是需要同时启动的五个固定角色。主 agent 在 `docs/progress.md` 的现有进度中简记分工和交接；当前科学决定仍只在 `docs/task_plan.json` / `docs/model_spec.md` 中维护，不建立各角色自己的当前方案。

各职责采用外部方法与软件时，按[阶段性接入](open-source-reuse.md#谁使用何时使用交给谁)明确具体模块、输入、可检查输出和接收者；选题必须交给设计可落实的预测与比较，软件必须交回实际运行。已有宿主足够时不增加 LangGraph 等第二工作流层；外部 Skill 不得自行派生固定团队、改变数据用途或科学决定。

## 每次委派写清什么

在派发消息中一次说明：本轮目标与适用要求；输入文件/来源及采用版本；允许修改的路径和禁止影响的工程；预期输出与来源格式；上游依赖；时间、工具或计算预算；校准或独立检验各自的完成条件、继续依据及受阻时应交回的结果。用户已明确的选择一并提供，未知内容不得写成已确认事实。需要独立行为验证时，只给任务与最低必要原始资料，不泄露预期答案或实现者怀疑的错误。

工作 agent 返回实际读取的来源、文件或代码位置，采用与未采用理由，执行命令/运行身份和产物，仍缺什么，以及实际用量。没有实际运行、全文阅读或独立复核的项目如实注明。主 agent 读取产物、核对关键事实再采用；资料不全或时间到达时交回已有结果，不补写成功。

## 依赖、写入与计算协调

- **可并行：**互不依赖的文献路线、不同数据集的条件核对、独立模块的只读审查，以及实现完成后的数值复算与交付复核。复用已核查且仍适用的来源，不靠重复搜索制造独立性。
- **按顺序：**明确用途/数据角色后定比较；方法确定后实现和检查；依据开发结果选择并冻结；随后进行独立评价，再决定采用、继续或停止。依赖尚未返回时不启动下游计算。
- **写入各有归属：**共享目录里，一个文件同时只有一个负责修改的角色；必要时使用隔离副本，由主 agent 检查差异后合入。提示词写“只读”不等于宿主创建了只读沙箱，不把隔离假设当成实际权限。
- **计算统一登记：**主 agent 或明确指定的唯一调度者预留并记录实际模拟调用，包含失败、重试和确认计算；并行运行前核实任务身份及资源。不同 agent 不得重复启动同一候选，换角色或续接不重置预算。
- **变更通知受影响角色：**目标、指标、规则版本或数据用途改变时，先核对影响再更新共享状态；旧结论保留其版本，不将不同阶段结果拼成同一模型的验证。

分歧回到原文、源码和数据处理判断，不能靠多数表决认定科学事实。独立复核也可能有相关错误；主 agent 对采用修改、保留分歧和五项完成状态负责。运行异常与未完成的比较不改写成有效阴性结果。

## 何时保留多 agent，何时顺序执行

先判断分解带来的并行收益或独立复核价值是否超过沟通、重复读取和整合成本。简单修改可由单 agent 完成；正式研究交付尽量安排未承担相应实现的角色核查原要求与实际产物。宿主不支持或资源不足时，由一个 agent 顺序承担同样职责，并明确“未进行独立 agent 复核”，不能换个角色名称冒充独立审查。

用少量真实任务比较实际遗漏、错误完成声明、错误数据用途、重复仿真和新引入错误，同时记录耗时、计算调用及可获得的工具/token 用量。相同输入和预算下的单 agent 与多 agent 比较才适合讨论相对效果；只有“执行稿加一次独立复核”时，报告新增发现与开销，不声称等成本优越性。指标不可获得时注明，不推算不存在的精确成本。

## 方法依据与采用范围

- [OpenAI 官方 Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)：采用读取密集任务分解、写入责任和权限边界的建议；具体工具与并发数以当前宿主为准，不照搬其他 CLI 配置。
- [Anthropic 多 agent 研究系统实践](https://www.anthropic.com/research/multi-agent-research-system)：采用明确子任务、输出和资源约束的组织经验；该检索系统的效果与成本不直接外推为神经建模收益。
- [Cemri 等，Why Do Multi-Agent LLM Systems Fail?](https://arxiv.org/html/2503.13657v2)：验证者仍可能停留在表面检查，因此复核原目标和原始产物，不能只检查运行成功或六个标题。
- [Kim 等，Towards a Science of Scaling Agent Systems](https://arxiv.org/html/2512.08296v1)：任务可分解性与顺序依赖影响多 agent 效果；这里只借鉴分工判断，不承诺该研究的量化收益能在本技能复现。

本页是基于上述方法与本技能实际需要的适配。行为效果按[技能测试](workflow-checks.md#检查技能本身是否有效)记录，论文、角色数量和多个 agent 的一致意见都不构成本项目已验证的证明。
