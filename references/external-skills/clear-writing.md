# 清楚、准确地表达科研内容

本页是面向本技能的署名适配，以 plain-language-zh 的可理解性方法为主，吸收 shuo-ren-hua 的用词原则和 Humanizer-zh 的信息保护规则。三者共同形成这一份规范，不叠加三套写作流程。正文、提问和选项、进度、方法说明、表格、图内文字、图注、网页及其他交付中的可见文字均适用；已有稿件修改也遵循本页。独立安装这些技能不是使用本规范的前提。

## 与 anti-defensive-writing 的分工

先依据实际方法、数据和本轮问题确定能成立的结论，再按 [anti-defensive-writing](anti-defensive-writing.md) 组织科学贡献及支撑结果，最后按本页改善表达。两者修改同一份内容；日常进度、问题选项和界面提示直接说明实际事项，不套论文叙事。

| 需要处理的内容 | 分工与边界 |
|---|---|
| 问题、贡献、比较与结果的组织 | anti-defensive-writing 负责突出真正成立的科学价值；本页不改变研究问题、主要指标、比较对象或六项交付顺序，也不把论文改成操作流水账。 |
| 用词、句子、表头、图内标签与图注 | 本页负责让读者理解具体对象、变化和依据；保留必要的正式程度、术语、数学定义和信息量，不强行口语化或规定每句只能有几个分句。 |
| 不确定性、反向结果与局限 | 保留会影响判断的真实条件、未改善指标和未完成工作，写清具体事实及影响；去掉无依据的自我贬低和重复免责声明。不为了增强说服力隐藏偏差，也不把局部偏差扩大成整个研究无价值。正文解释实质问题，末句按原要求概括主要局限。 |
| 表达与科学含义发生冲突 | 用户要求、事实与支持范围、既定交付要求优先于风格偏好。简化会丢失含义时保留准确术语并解释；新增实验或改动科学目标回到原研究流程，不能由文字润色决定。 |

## 通用写法

- **先说清对象、动作和实际结果。** 普通词足以表达时用普通词，避免把内部代号、工作简称或生造词直接交给读者。首次出现的必要术语在附近解释，后文用法一致；不要求读者来回查词表才能理解。
- **补足理解所需的背景。** 提问交代当前选择，进度交代正在做什么及下一步，方法交代如何实现，结果交代发生了什么及为何重要。按逻辑连接完整句子，段落各有重点；同一意思不反复铺垫，不为简短删掉必要因果和条件。
- **数值与判断放在一起。** 保留单位、比较对象、方向、统计口径、样本层级及适用的不确定性；只解释已有数据，不为使句子具体而补造数值。区分正在、计划、已完成，以及可能、相关、因果；修改文字不提升结论的确定程度。
- **遵循输出语言与文体。** 中文交流和交付默认使用自然的中文科研表达；明确的英文论文、图件或期刊要求优先。不强行翻译模型名称、通用缩写、公式符号和单位，必要时附中文说明；代码标识、命令、路径、链接目标和原始数据字段保持准确。逐字引文、论文题名及软件标识保留原文，通俗解释放在旁边，不能改写引文内部后仍作为直接引语呈现。
- **按含义改写，不设词语黑名单。** 技能规则、代码或来源中出现术语，不等于面向用户时必须照抄。解释图表时不能仅凭词面自动替换，保留原始定义和所指对象；原句已经清楚时可以不改。

| 原表达及适用条件 | 面向用户的写法示例 |
|---|---|
| 冒烟测试，实际仅检查启动和主要步骤 | 先快速检查程序能否启动、主要步骤能否运行；不能据此写成模型已通过生物学验证。 |
| 参数扫描 | 按预定范围尝试多组参数，比较各组结果。 |
| 冻结基线配置 | 把当前模型和参数固定下来，作为后续比较的基准。 |
| 冻结后独立确认 | 确定候选参数后，用未参与选参的条件或随机实现再次检验。说明实际使用哪一种，不能把随机实现称为新的生物样本。 |
| 验收门禁未通过 | 结果尚未达到事先规定的要求，并说明是哪项要求、实际差多少或缺什么。 |
| 招募更多神经元 | 若实际量是对刺激产生响应的细胞数，写“更多神经元开始对刺激产生响应”；若是原有细胞的发放频率增加，写“这些细胞放电更频繁”。没有刺激时不能补写刺激；实际含义不清时先查指标定义。 |
| 闭环调控 | 确实存在反馈时可写“根据监测到的活动调整刺激（闭环调控）”。仿真结束后挑选下一组参数，写“根据上一批结果调整下一批参数”，不能称为已实现生理反馈。 |

示例用于说明信息应怎样展开，不强制逐字替换，也不能用例句中的前提补造本项目事实。

## 图、表与其他可见文字

| 载体 | 具体要求 |
|---|---|
| 提问、选项与阶段说明 | 按[分轮讨论](../interview.md)的题数与节奏，问题简述背景，选项解释含义及影响，推荐交代理由。已知答案沿用；增加说明不增加审批。阶段说明讲实际方法、结果和待做事项。 |
| 正文、摘要与方法说明 | 保留原六项交付及科学论述。专业名称首次出现时说明其含义；公式旁解释符号与单位，数学表达不能被泛泛口语替代。完成与支持范围根据实际检查分别表述。 |
| 表格 | 标题说明比较什么，行列名写清对象与指标，单位放在表头或相邻注释。条件简称、分母、误差表示、样本量层级及缺失值含义在表内或表注解释；未测、失败和不适用不能统一填 0。必要参数表保留符号或代码字段，同时提供可理解的名称或定义。 |
| 结果图与方法图内部 | 检查标题、坐标轴与刻度、图例、色标、面板标题、箭头、流程框、标注、嵌入表格及显著性说明。标签用短而准确的名称，单位不省；复杂解释放到相邻图注，不能用缩小字号或留下无人能懂的代号解决拥挤。图的结论标题必须有实际结果支持。 |
| 图注与单独导出的图件 | 图及其图注应让目标读者不查正文也能知道对象、条件和指标。解释图中缩写、线条/阴影、误差条、样本层级及关键处理；单独导出时一起提供图注或必要注释。B、D0、D(u*) 等内部记号应配有“基础模型”“未调控的负面影响模型”“所选调控方案”等实际含义。保留示意、实际构建结果及实测数据的区别。 |
| 网页与其他交付 | 页面标题、状态、按钮、提示、图片替代文字、演示图和导出材料沿用相同名称及完成状态。简短状态旁可展开具体原因；颜色、对钩与简短标签不能掩盖尚未完成或未获支持的事项。 |

文本清理优先改绘图代码或可编辑源文件中的标签，再重新导出；数值、统计、曲线、箭头所表示的关系及对照不随文字修改。计算设定未变时复用已核对的数据，不为改字重新仿真；若发现单位、定义或算法错误，按原规则修正并重算受影响结果。只有已有图片可用时先核对原意，再采用可检查的编辑方式，保留原图；不得凭空重绘数据来改字。按[图件规则](../literature-figures.md)保留源文件和可重绘材料。

## 输出前如何检查

1. **生成前确定名称。** 在现有方法、参数定义和图件设计中沿用一致的对象/条件/指标名称。面向读者的简称和代码字段可不同，但对应关系清楚；不新建另一套参数表或术语管理系统。
2. **改后对照原材料。** 核对正文、表、图和网页中同一结果的数字、单位、方向、分母、样本层级、条件、完成状态及结论强度。再读一遍：不了解项目内部代号的目标读者能否理解？通俗表述不得把指标改善写成功能恢复或临床疗效。
3. **实际查看导出物。** 打开本轮交付图件及适用的网页/文档，检查中文字体、负号、上下标、换行、截断、重叠及缩放后的可读性。只检查绘图源码、自动识字或文件存在不算完成；未实际查看的内容如实标记待检查。
4. **复用原检查记录。** 图件检查写入现有 `figure_plan.md` 的实际查看记录，其他文字问题并入当前交付复核/进度记录，写明具体输出、发现与处理；不另造检查总表。修订后重查受影响正文和图表，源内容变化时旧检查不能继续代表新版。程序通过不能证明文字清楚或科学含义未变。
