**修改范围：**选择 deep-research、academic-paper、academic-paper-reviewer、academic-pipeline 中相关方法，改写为神经网络研究的输入、计算实验、结果与复核流程；新增建模环节，调整默认提问方式、阶段确认和输出位置。不分发或运行上游完整插件、代理团队、钩子和脚本，不声称通过 ARS 完整流程的检查。

## 位置与两种入口

```text
现象与研究问题 ←→ 文献研究、候选机制与研究设计（ARS 适配）
                              ↓
详细构建调研与分轮追问 → 构建 → 运行 → 文献/实测比较与优化
                     （zm_neuron_network）
                              ↓
实际方法、数据图件与结论 → 写作 → 审阅 → 修改与复核（ARS 适配）
                              ↑          │
                              └─ 补充计算请求 → 返回建模或分析
```

- **作为科研流程中的环节：**上游已有研究简要说明、方法设计、文献和数据时，先读取并承接，补充其中尚未完成的领域调研；把本轮计算实验结果交回后续写作和审阅。已经独立安装 ARS 的宿主，也可按下面的交接内容调用本技能，不要求改变其上游源码。
- **独立建模：**用户只委托模型、运行或分析时，使用相同的研究设计和结果核查方法，交付到约定范围即止。论文、投稿格式和系统综述不自动成为必交内容。
- **完整研究委托：**用户要求从想法到研究报告或论文时，由当前主助手组织总流程，调用本技能完成计算部分，再继续已委托的写作与复核。不要新建另一套相同模型工程，也不要声称已向上游仓库注册插件或创建独立审稿团队。

## 研究设计交给建模的内容

在现有 `docs/progress.md` 和 `docs/model_spec.md` 中承接，不新建重复表格。上游材料不完整时详细调研并分轮追问，不要求用户独自补齐技术参数。

| 上游需要说明 | 进入建模后如何落实 |
|---|---|
| 观察到的现象、对象、条件与测量定义 | 明确物种、脑区、细胞群体、状态和读数；区分观察与原因假说。 |
| 科学问题、候选机制与替代解释 | 提出能区分候选的预测、对照或消融；没有定论的机制继续保留候选身份。 |
| 文献、作者代码、数据及方法比较 | 深读构建方法和补充材料，核对所用方程、原参数、适用条件与代码版本，形成来源到本模型的对应。 |
| 数据用途、比较协议与主要指标 | 首次选参前确定拟合和独立评价用途、重复单位、观察窗与比较标准，避免用结果倒推原假设。 |
| 本轮范围、资源及已有决定 | 恢复原始要求和有效决定，明确必需产物、校准指标和留待独立检验的问题。区分单批计算安排与用户授权的总资源，累计记录实际消耗。 |

上游写明“使用某类神经元模型”不等于完成模型选择。核查它是否表达目标机制、是否与观测和时间尺度匹配；有实质问题时返回讨论，而不是机械实现。

## 详细调研与提问贯穿计算实验

采用 ARS 的问题澄清、假设检查、反向文献检索和方法比较，按本技能的[调研与追问](../interview.md)执行。**本方向默认需要详细研究和持续提问，不因接入总流程而压缩为一次开场问答。**

1. 从现象、正常/特殊条件、候选原因、可观测信号开始，查原始论文、方法、补充材料、对应实现与数据。完整新建通常以 3–5 篇直接相关构建论文起步；按方法差异和参数缺口补查，不靠篇数证明充分。
2. 研究神经元表示、数量与缩放、三维空间、连接生成、突触机制、输入与静息活动、初态、求解及记录分析的适用方法；目标依赖的机制继续深入。共同遵守[构建方法](../construction-methods.md)与原要素清单。
3. 沿用上游已经确定的方向、档位和资料用途。需要选方向时先比较可行的科研问题，方向明确后推荐建模档位。每阶段按[访谈细则](../interview.md#构建讨论与额外的科学讨论)用资料和已有结果检查候选预测与读数，向研究者提出尚待选择的取舍。完成后提出开放式改进时，按[新轮次入口](../interview.md#完成模型后继续优化)研究新方向。
4. 搜索不支持当前假说的结果，区分物种、脑区、实验状态、模型层级和观测定义造成的差异。对每条引用分别核实“文献存在”和“原文支持当前说法”，不能只核实 DOI。
5. 资料允许比较但不能裁决时，实施已委托的局部计算，保存结果，再带着新发现追问。网络运行和文献/实测比较出现新偏差时，回到受影响的机制、参数或实验设计。

这里采用“有依据的建议 + 科学讨论”，没有启用 ARS 的纯非生成式 Socratic 模式。已有答案和常规实现不反复请求确认，必要科学选择也不因“持续推进”而被跳过。

## 建模交回科研流程的内容

实际构建、运行和优化仍由本技能承担，按现有工程位置输出；交接以文件链接、版本和结果状态为主，不复制数值到多处维护。

| 交回内容 | 主要位置与判断 |
|---|---|
| 可复算的当前模型与方法 | `model/`、`docs/model_spec.md`；明确实际神经元模型名称/变体、群体映射、方程、数量、空间、连接、突触及仿真条件。 |
| 来源与参数的对应 | `docs/sources.md`、`docs/research/parameter_mapping.csv`；保留来源原值、单位、转换、实际取值、采用理由与实现位置。 |
| 每步实际构建结果与运行记录 | `results/<run_id>/`、`results/index.json`；链接代码版本、实际参数、随机设置、原始输出与检查，区分已运行、失败和未完成。 |
| 文献/实测比较与研究图件 | `analysis/output/`、`docs/results.md`；每个面板对应实际数据、处理方法、统计单位和绘图代码，说明文献图学习来源。 |
| 结论、替代解释及剩余问题 | 结果报告中的“主张—来源/运行—指标/图—适用范围”对应；分清数值正确、模型符合观测与机制得到支持。阴性结果和未解释偏差一并交回。 |

没有运行时只交回方案及未完成部分，写作环节不能补写为结果。冻结后有判别力的独立比较可以支持阴性结论。运行失败或检验精度不足时交代仍缺什么，保留原定主要指标。

## 写作、图件和审阅如何使用结果

- **写作与表达分工：**ARS 的 academic-paper 方法负责问题、方法、结果、讨论与引用之间的关系；[anti-defensive-writing](anti-defensive-writing.md)负责表达组织。两者引用同一份实际模型结果，遵守[接入边界](../skill-integrations.md)，不各生成一套不同的数值或实验故事。
- **图件：**按[文献图规则](../literature-figures.md)先查看适用研究的真实图件，再使用自身数据形成能回答问题的面板；保留原始数据、作图数据、误差定义、样本单位和绘图代码。不把生成式示意图当作数值结果，也不强制采用上游 APA 风格。
- **审阅：**采用 academic-paper-reviewer 的方法、领域、替代解释和读者适用性等视角，逐条指出问题所在、依据、影响与具体修正。未实际运行多名审阅者时，称为多视角复核，不称独立同行评议。审阅意见及其推荐文献也要核实。
- **修改与复核：**保留“意见—处理—修改位置—新增结果—复核结论”。修改论点后检查摘要、正文、图表、图注和参考文献的一致性。纯审阅只出意见；已经委托修改时继续完成适用修改，不反复索取阶段许可。
- **报告形式：**跟随用户语言和交付范围；正式论文按目标期刊核实格式、披露和数据说明，不能为局部模型报告自动生成虚假的伦理批准、作者贡献或基金信息。

## 审阅后返回计算实验

先用[论文主张和已有证据](../scientific-questions.md#判断补充实验是否必要)判断每条建议。删去建议的实验后，核心结论仍有充分依据，就在原意见旁说明理由并结束该项。确有判别价值时，再写明允许改变的因素、数据用途和主要判据。

| 反馈性质 | 返回哪里、怎样完成 |
|---|---|
| 数值引用或表述不一致，原数据充分 | 修正分析或文字，复核受影响图表；不额外运行模型。 |
| 需要新的观察窗、统计或图形，原记录充分 | 重分析并保留分析版本；不声称重新仿真。 |
| 现有记录缺少原主张必需的对照 | 说明哪种结果会改变判断、最小的可比条件及停止点。在已授权且未暂停的范围内执行，保留原结果。 |
| 改变科学问题、主要假说或数据用途 | 说明变化依据，与研究者讨论后修订设计；不能把新探索改称原预设验证。 |

补充计算后，按原始要求在同一最终采用版本上复核本次修改和受影响的旧结果。参数范围或单批预算用完而仍有偏差时，查清观测、实现或机制等实际原因，修正后重跑所需比较。用来决定修改的资料归入开发，另留独立资料检验冻结后的预测。完整建模只在用户要求停止，或授权内确实无法解决的外部阻碍使剩余工作无法推进时暂停。交回受影响的要求、实得结果、已尝试的解决办法和恢复条件。

交接时复用本工程的任务计划和分析记录：分别传递运行、校准、独立评价、科学回答和交付状态，以及实际采用版本、数据用途、未解决项与下一动作。由 [交付复核](../project-checks.md#记录与运行约定) 核查实际产物，不将程序通过或写作完成转换成科学结论成立。需要多 agent 时按 [动态分工](../delegation.md) 安排，不默认启动上游的固定团队。
