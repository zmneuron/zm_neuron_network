# 把一版科学方案对应到代码和结果

在实现前给出方案版本。当前 `docs/model_spec.md` 同时承担完整构建方法，按[调研与构建规范](construction-methods.md)引用方法比较和参数对应条目。新建模型先选定本次代码的运行入口和命令，再注明研究问题、首个实验、后端、输入数据标识、依赖版本、完成判据和计算预算。目录与模块按[工程结构](project-layout.md)组织；下表仅示意怎样把一个要素写入配置、代码和输出，数值不作为新模型的默认值。

| 要素与建模决定 | 配置字段、值或范围、单位 | 相对路径与函数职责 | 输入、输出文件与字段、单位 | 从输出核对的算法及允许误差 |
|---|---|---|---|---|
| 07 固定入度示例 | `model/config/model.json` 的 `connectivity.E.in_degree=4`、`connectivity.I.in_degree=2`，单位均为每目标的不同来源细胞数 | `model/network/connectivity.py` 按来源群选取伙伴并建立有向连接；`model/run.py` 只调度运行 | `results/<run_id>/raw/connections.csv` 含 source_id、target_id、source_group、target_group、weight_uS、delay_ms | 按每个 target_id 和 source_group 统计不同 source_id，每个目标须为 4 E、2 I。逐边查自连、重复、权重和延迟。 |

## 方案、实现、仿真和分析分别标识

| 记录 | 何时改变 | 保存位置与用途 |
|---|---|---|
| 科学方案版本 | 研究问题、模型假设、协议或指标解释改变 | 当前完整 `docs/model_spec.md`；记录上一版、修改原因、受影响要素和要重验的输出。历史版本按工程归档规则保留。 |
| 模型实现版本 | 模型代码或接口改变，包括拆分文件 | 指向实际源码的版本记录或单份归档；说明是否改变动力学和随机数使用。纯重构不自动改变科学方案。 |
| 仿真 `run_id` | 每次独立仿真；同一仿真续跑时保留标识并关联分段/尝试记录 | 原始输出及 `run.json`，绑定实际模型实现、运行配置、输入、种子、环境和状态。续跑按[恢复规则](execution-management.md#保存状态是否足以继续)记录连续性，不能算作新增独立重复。 |
| 分析版本与记录 | 指标、时窗、统计或图形计算改变 | `analysis/output/` 中的分析记录；绑定原始运行集合、分析代码、实际设置与命令。使用当轮科学方案，但不能改写原仿真的产生版本。 |

一次运行的最小记录包括：运行标识、方案与模型实现标识、可恢复的源码位置、所用构建方法与参数对应版本、实际配置和输入位置、实际细胞/坐标与连接/突触数据位置、命令与工作目录、关键软件版本、随机来源与种子、初始化与求解设置、条件和重复、开始时间与耗时、是否完成及必要检查结果。信息已有明确文件时引用即可，不要求把同一字段重复写入多个清单。方法和参数对应表随该实现版本一并保存，不在每个运行目录重复复制。

分析记录单列原始运行及所用数据、分析实现与设置、命令、时间和检查结果。例如恢复指标从前向窗口改为截至当前的窗口，应更新当前方案和分析版本，原始仿真保持原 `run_id`、模型版本、命令与耗时；不将重算指标记成新仿真，也不复制一套原始轨迹来制造新运行。

当前交付采用哪些运行及分析，由 `results/index.json` 明确列出，并能定位到正式数据表和图件的分析记录。源码或配置有改动但没有对应检查和结果时，不能把旧输出改标为新版本结果。仅补充已用参数的来源定位可更新说明；采用值、生成算法或构建解释改变时，应记录版本及要重新核对的内容。

## 修改后哪些结果仍可使用

修改前先沿“参数/代码/输入 → 实际对象和动力学 → 原始记录 → 指标 → 图表和结论”判断影响，记录在当前方法或进度中即可。以下是处理起点，具体取决于真实依赖；有反馈耦合的模块要检查反馈返回路径，不能仅按文件所在目录划定影响。

| 修改内容 | 原结果怎样处理 | 本轮需要重新完成什么 |
|---|---|---|
| 文字、来源定位或命名说明；实际含义和值均未变 | 保留原运行和分析身份，修正文档对应。 | 核对说明与实际设置；若解释发生实质变化，另行更新科学方案和结论。 |
| 排版、颜色或图注；数据筛选与计算未变 | 复用原始数据及指标表，更新图件和分析记录。 | 重绘并检查图中数值、单位与样本说明，不重新仿真。 |
| 指标算法、时间窗、筛选、聚合或观测转换 | 原始记录覆盖所需状态与分辨率时可复用；旧指标/图不能直接用于新定义。 | 对受影响的全部比较条件一致重分析，保留原主要结果及数据用途。缺所需记录时才补充对应仿真，不能推造缺失状态。 |
| 细胞、突触、拓扑、数量、输入、初态或数值协议 | 旧运行仍属于旧配置，可作为原版本比较；受影响的结果不代表新模型。 | 更新方法/参数，重建相关对象，执行受影响组件和网络计算；重算其下游分析、图件和结论。 |
| 代码重构、后端/环境或并行设置 | 先明确拟保留的模型语义和随机过程；历史结果仍保留产生它的版本。 | 做适用的等价性和数值比较。检查通过可引用原结果支持未变部分，但不能把旧运行改称新实现已完成的正式计算。 |

同一工程的无关条件或没有受影响依赖的模块可引用既有结果，说明理由和版本；不能无依据重跑全部，也不能默认未改文件名的结果仍适用。影响不明时先做最小相关比较，未明确前标记待核对。

[联合检查](project-checks.md)按版本、文件和整份配置核对，不会自动判断局部改动是否等价。旧原始数据可以复用，不表示其旧完成记录仍适用于新方案；为当前任务实际执行相关的一致性与适用性检查，明确检查所用当前配置、旧数据及其原始仿真版本。检查操作与生成数据的仿真分开记录，不能手改旧检查的版本/数值或跳过失败项来制造通过。

当前结果索引仅采用已完成所需检查、与当前结论相容的运行和分析组合；注明复用的旧运行及其原始版本。旧数据和图保留其产生条件，需要更新的部分标为待重算，不删除或伪改原记录来维持“全部完成”。单纯缺少新的作图样式不使原仿真失效。

已有后台任务继续使用原来的源码、配置与输入；新改动安排到另一候选，按[执行管理](execution-management.md)判断等待、恢复或重启。保存的动态状态也有适用版本，不能跨配置直接续接来省略必要计算。

## 比较和更新

相同方案可以有不同实现。明确需保留的目录、文件职责、函数入口、配置含义、单位、随机数使用方式和结果定义。重建或拆分实现时使原实现仍可恢复，用相同的小组输入分别运行。先检查接口和模型语义，再比较离散结构和连续数值。需要逐边复现随机图时，生成器、候选顺序、抽样顺序和软件版本都影响结果。

同一实现复跑时固定原始输入、配置、种子、步长、初始化和相关软件环境。在运行前列出应完全相同的离散量，按单位约定连续量的绝对或相对容差，写明理由。运行时长属于资源记录。若设计的本意是比较独立随机重复，预先选择重复单位、种子策略、统计量和允许差异，例如网络实例的招募比例分布及其区间，再判断模型预测的分布是否稳定。

规划可随用户意见或新资料修订。更新时先保留可恢复的旧代码、配置、环境和相关结果，在工作位置完成改动与检查，再同步当前代码、完整方案、结果索引和使用说明。旧版本从当前交付移至版本管理或独立归档；当前运行所需的原始输出继续保留。仅有 Git 提交号但存在未记录修改，或只保存校验值而没有源码，均不足以恢复原实现。新版本未通过必要检查时不替换已通过的版本。重建相同方案只增加实现标识，不把代码写法的变化混同于科学设计的变化。

复用研究者明确指定的既有模型时，核对该模型自己的字段、单位、比较标准和复现命令。新建任务不依赖技能作者的本地工程。
