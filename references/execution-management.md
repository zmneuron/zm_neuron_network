# 计算成本、后台运行与中断续接

用于正式扩展、批量候选、长运行或接续已有计算。普通短运行沿用相同原则，不强制增加后台服务、调度器或保存状态功能。这里只规定执行与恢复；参数搜索见[运行与优化](run-compare-optimize.md)，修改后的结果适用性见[版本规则](versioning.md#修改后哪些结果仍可使用)。本页内容并入已有 `docs/model_spec.md`、`docs/progress.md` 和 `run.json`，不新建另一套进度表。

## 扩展前测量全过程成本

阶段执行及面向用户的展示使用同一份记录，详见下节；计算进度与科学验证结果不能互相代替。

采用实际后端、输入方式、记录密度和有代表性的网络规模完成一次短运行，记录模拟时间与真实耗时，区分以下阶段：

| 部分 | 需要测量或估计什么 |
|---|---|
| 构建与准备 | 读数据、建立细胞/连接、机制加载或编译、初始化；重复候选能否复用哪些对象及条件。 |
| 积分与事件处理 | 模拟时长、实际耗时、细胞/接触数、事件负荷、步长及线程/进程数。记录该试跑覆盖的活动状态。 |
| 保存与后处理 | 原始记录写入、必要的状态保存/恢复、指标和绘图、关闭与清理的耗时。短积分结束不等于整个任务已结束。 |
| 资源峰值 | 内存、磁盘增长及可用空间；并发任务共享资源时的总需求，不能只按单任务平均值估计。 |

按条件数、独立重复、候选数及验证计算估计总成本，预留失败重试和分析的余量。优先用实测的不同规模或并发设置估计；只有一个小规模样本时给出估算范围及可能的非线性因素，不把积分耗时简单乘倍数当成确定的结束时间。高发放、长延迟队列、密集连接和完整记录可能改变资源需求。

在现有方法中写明本轮时间、内存、磁盘或评价次数的适用上限、并发安排与停止条件。根据实测吞吐量选并发，不默认线程越多越快；避免多个候选同时占满各自声明的全部核心。超出预算先减少不影响目标的重复开销或调整授权范围内的搜索安排；改变必需机制、规模、记录、比较或独立重复属于科学取舍，不能悄悄删减。尚未获得更多资源时保留已完成部分、下一批计算及未满足要求，不因当前会话时间不足降低原完成标准。

需要约化或代理时，先按[模型职责与保留量](method-discovery.md#点模型优先与形态需求)明确输入范围、目标量及容许误差；关键候选仍由符合约定的主体模型检验。按目标检查低发放、状态转变附近或必要局部量，不能只用总体相关性证明近似有效。不统一规定细胞数、10 秒时长或三次重复；规模、时长与重复由目标时间尺度、变异及相应敏感性决定，不能把网络中各细胞当作独立动物重复。

## 启动与跟进实际任务

1. **先查已有任务。** 核对运行标识、主机、进程启动信息或调度器作业号、命令/工作目录、配置版本、日志和最近输出。进程号可能复用，日志增长也不单独证明任务正确；确认是否仍在执行同一任务后再决定等待、恢复或重启。不要并行启动两个任务写同一结果目录。
2. **固定本次输入与实现。** 保存实际命令、环境、源码与配置、条件/重复和随机设置；运行中的依赖文件保持不变。新改动使用另一候选版本，不直接覆盖仍被任务读取的文件。首次换目标平台时在该环境检查依赖、机制编译、入口及一次代表性计算，未测试的平台不宣称可用。
3. **核对阶段与进展。** 区分排队、构建、积分、保存/分析、已完成、失败和中断；状态名称可沿用原工程。结合进程/调度器状态、模拟时间、已完成条件和输出判断。只报告实际观察到的进展，注明最近检查时间；估计剩余时间时保留不确定性。
4. **按状态处理。** 健康运行继续跟进；失败先保存日志和原因。仅在本任务授权及预算内、确定原实例已结束、失败可恢复且有明确重试上限时重试。数值异常、参数不适用或反复资源不足应返回对应检查，不无限自动重启。已完成任务转入输出核对，不因未看到最终文字而重新运行。
5. **完成后核对产物。** 逐条件和重复检查实际模拟时长、原始记录及必需指标，再进入比较和报告。进程退出、作业提交成功、文件非空分别只是执行信息，不能代替完整性或科学判断。

后台运行并不保证当前会话结束后 AI 仍持续监控。在当前可执行任务内继续检查并完成后续工作；确实需要交接时写明已核实状态、任务位置、剩余工作和下一检查命令，不虚称仍在自动关注，也不为一次计算另建永久自动化。

## 保存状态是否足以继续

先检查所用后端实际支持的保存/恢复范围。保存膜电位或累计尖峰通常只覆盖部分状态；按模型核对神经元/突触/可塑性状态、求解器时间与内部状态、待送达事件、随机过程、外部输入读取位置，以及记录输出的续写位置。仅记录一个种子不能代替已经推进的随机状态。

需要连续恢复且后端支持时，在相关小模型上比较“连续运行”和“相同时刻保存、关闭后恢复”的输出：离散事件、状态、时间轴和统计量按预定标准检查，确认无漏事件、重放、重复记录或间隙。保存文件是否完整及与实现、配置、输入、并行设置的兼容性也须核对。未完成这些检查时，只能说明保存了哪些内容，不能承诺精确续跑。

同一次逻辑仿真的续跑保留原运行标识，并记录每段/尝试的起止时间和保存状态来源；已有系统采用分段标识时，显式关联父运行及时间覆盖。不同段不是独立重复。模型改动或恢复条件不兼容时，按[修改影响](versioning.md#修改后哪些结果仍可使用)处理，不能把旧状态直接套到新模型后声称同一次连续实验。

后端不支持可靠恢复时，在预算允许且原实例已结束后从头运行新的尝试，保留失败部分并标明不完整；不得把独立初始化的多段拼成连续轨迹。若科学设计允许分段独立试次，可按该设计执行，但需保留其独立初态与试次身份。

## 让用户看见阶段与验证结果

开始时简洁展示本轮适用主线：**明确问题 → 调研讨论 → 确定方案 → 逐步构建 → 运行比较与优化 → 解释交付**。阶段可按真实工作拆分，不为每次函数调用生成一个阶段。基础模型、负面影响、调控是按需的科学部分，归入相应构建和比较步骤；不是必须同时启用的三套流程，也不必把六步与三部分机械组合成十八项。

每个主要阶段开始时说明正在做什么及判断依据；结束时输出简短说明：**实际怎样构建/处理 → 用什么检查 → 得到什么结果及相应图 → 剩余问题与下一步**。细胞、数量/空间、连接/突触、输入/求解等分别引用已有方法和实际产物。基础部分交代采用模型和活动；负面影响交代生物变化—参数/机制修改—实际不利结果；调控交代可控作用、联合筛选及确认。图来自该步实际产物，示意图明确标注；尚未产生图、未记录某变量或本步不需要图时直接说明，不为展示捏造曲线或重跑仿真。

| 标记 | 只能表示什么 |
|---|---|
| ✅ 已完成/已通过 | 本项确实执行且相应记录、产物和检查成立；科学要求的勾还须满足该要求 |
| ⏳ 进行中 | 最近核实的实际阶段，并显示核实时间；旧记录不代表进程仍活着 |
| ☐ 待完成/待评价 | 尚未执行、检查不够或没有所需数据 |
| ❌ 未通过 | 已做检查但未满足标准，保留失败原因和影响 |
| ⏸ 受阻 | 资料、资源或必需决定不足，说明下一动作 |
| — 未纳入本轮 | 依据原范围不适用；不能显示成绿色对钩 |

“校准比较已经做完”与“校准满足标准”分两行或明确分两句；有效阴性可以是已完成的研究，却不能给“恢复有效”打勾。运行结束、约束满足、独立支持、问题回答、交付完整仍是五项独立判断。不画虚构百分比或预计时间；只有分母与范围已知时才显示进度比例。

沿用 `analysis.construction_steps` 的 `status,method_ref,observation,data_ids,figure_ids,check_refs`；补充简短的 `method_summary`、`component`（`shared/baseline/adverse/regulation`）及进行中项的 `last_checked_at`。`pending/running/blocked/failed/not_applicable` 不打勾。开始时在 `review.model_components` 登记适用部分，完整调控包括三个部分；新任务设置 `review.display_progress: true`。没有完成记录不能只因配置写了某模块就说它建成。

用 [show_progress.py](../scripts/show_progress.py) 从已有记录生成状态表与图件入口：`python <skill_dir>/scripts/show_progress.py --project <工程>`。这是只读呈现，不是另一份状态台账；`docs/progress.md` 保留关键决定、近期核实和下一步，表由原记录重新生成。正在工作时在对话展示本阶段及有变化的行，阶段结束交代实际方法与结果；避免每批候选都重复整张表。

最终 [完成检查](project-checks.md#在阶段转换恢复和交付前执行复核) 返回实际的 `progress.table_markdown`。缺表时另给 `required_progress_table` 供补入正文，后者是待复核稿，不代表已经通过。把当前表放入六项交付的第 5 项，报告和对话都显示，再重查正文并导出发送稿；不能把表放在摘要前、只存成文件或自行给所有步骤加勾。表中任何未完成/未通过项须说明原因与影响，完整正文仍按原科学问题解释结果。

### 在 Codex 内查看

用户需要网页时，用 [build_viewer.py](../scripts/build_viewer.py) 导出本地只读页：读取同一版本、阶段、方法说明、检查和实际图件，在 Codex 支持的浏览器面板中打开。仅显示记录已有的内容；当前导出是**已保存记录的查看页**，重新生成后才反映新记录，不冒称实时求解、后台持续监控或已能中途续算。默认本机或离线访问，不能为展示上传科研模型/实验数据。

页面默认从简：首页仅显示模型部分与验证状态，构建说明、结果图、完整报告和记录信息按需展开。避免重复说明、筛选栏和多层导航；精简界面不删原始记录、不改变完成判断，也不省略完整报告的六项内容。

`python <skill_dir>/scripts/build_viewer.py --project <工程> --output <新的HTML路径>` 导出后，使用宿主的本地文件或浏览器展示能力实际打开并检查；没有该能力时交付 HTML 并如实说明。页面不覆盖原文件，只内嵌适用的项目内图片；超出大小限制时明确筛选展示内容，不改动原始数据。页面中的步骤和检查状态来自同一份记录，图件存在本身不赋予“验证通过”。

实时扩展另按实际需求接入已完成的数据批次：执行状态、记录可用区间、界面刷新与历史游标分开；缺失不是零，回看不是重新计算。结构/连接/活动/分析是信息视图，不能当作执行阶段。只有真实空间量需要时才加入三维；实际坐标、生成几何与展示布局分开，输入事件源不混算为动态神经元。查看器只读记录，不取得求解器控制权。

本轮借鉴用户可视化调研文档的状态分离、已完成批次和保存重开逻辑，先验证已有结果读取，不把整套三维/在线平台变成每次建模的前置工作。复杂交互图可按需复用 [Plotly HTML 导出](https://plotly.com/python/interactive-html-export/)；具有三维需求时再评估 [PyVista/trame](https://docs.pyvista.org/api/plotting/_autosummary/pyvista.plotter.export_html) 及维护接口。本轮普通阶段与已有图展示用无额外依赖的静态页面；2026-11-23 已定向核对上述官方页面，未据此宣称这些后端已集成或完成实时测试。

## 交接只保留一份当前状态

在现有进度中引用运行记录，简述：当前问题/方案、实际任务身份与状态、最近完成的条件和模拟时间、已用与剩余预算、可用的恢复点及检查情况、已保存结果、当前错误或待决定事项、下一条可执行动作。接手先重新核实实际状态再行动；旧进度中的“正在运行”不能当作当前事实。
