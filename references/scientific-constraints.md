# 让生物学依据真正约束模型与结论

新建研究模型、改变生物学情境或解释调控结果时使用。此页集中说明科学判断；详细查找、参数转换、场景和调控操作沿用对应细则。内容落在已有 `docs/model_spec.md`、来源/参数记录和 `docs/results.md`，不增加一套必填报告。只做格式或工程维护时不启动新的生物学研究。

## 运行前把决定结论的关系写实

在当前方法已有的问题/关键过程表中逐题补齐下列关系。探索小运行只落实当次问题；正式比较前落实其全部主张，不能看到结果后再把缺少的约束改成“不适用”。

| 当前问题与允许的结论 | 已观察到什么，原始资料在哪、条件是否适用 | 实际改变/保留的对象、方程和参数 | 从来源量到采用值的关系及主要未知量 | 本轮怎样检验，什么结果会改变解释 |
|---|---|---|---|---|

- **对象有实质对应。** 区域/细胞标签、投射颜色和细胞数量不自动构成特异性。指出本题依赖的内在响应、输入或连接等差异及依据。只有区域情境、没有特异约束时明确为该情境下的有效模型；不为显得详细强加形态、坐标或全脑结构。
- **观察与机制分开。** 影像相关、群体标记、胞体放电、连接强度和行为结局不是同一种量。跨物种、脑区、阶段、性别、制备与协议的迁移说明它支持符号、量级、范围还是定量映射；冲突资料保留原条件，不平均成一个“文献值”。
- **直接改动与后果分开。** 给出参考到场景的实际改动及作用位置，并说明预期由模型产生的中间/末端结果。仅改变下游增益时，只检验该有效路径假设，不能同时宣称已解释上游细胞病变。系统真实作用可能跨多个层级，依据支持时允许联合改变。
- **依据落到实现。** 原文方法/表/图、作者实现版本/函数、数据子集与处理对应到主参数表。区分原始测量、推导、拟合、继承假设和本次新假设；只引用论文题目或自己的方法说明不等于原始取值依据。独立构建路线的比较按[构建调研](construction-methods.md#深读并比较多篇构建方法)完成，实验背景文献不能替代数学/实现选型。
- **未知量仍需处置。** 对决定主结论的假设说明取值理由、适用范围或未知范围、参数关联和本轮处理。不能仅填 `assumption` 后停止。合理范围未知时可作明示的情境探索，不能把任意扫值说成生理范围；不按假设占比判合格，也不要求所有参数都可识别。

公开数据与代码要查实际可获取性；无适用数据时留下已查范围、可用替代及缺失影响。已有文献汇总值可以作相应层次约束；不能承诺一定找到患者数据，也不能取消用户原本要求的数据比较。检索过程随研究保存，临时文件或聊天工具输出不能成为交付中唯一的来源记录。

只有方向、资料来源和输出大类已定时，尚不足以宣布完整模型确定。把未解决事项分为“AI 继续查证”“已有授权下比较候选”“需研究者决定的实质取舍”，按[提问结束规则](interview.md#何时结束提问并进入实施)收束；不把所有未知参数变成用户问卷。

## 先看哪些结果已由设定决定

对主结论，先沿输入、连接符号、单调关系、归一化、饱和或硬性钳制判断是否能直接推出方向。目标节律或事件结构已写在外部输入时，先区分回路生成、传递与调制；需要对照时说明回放、打乱时序或改变反馈保留了哪些输入统计，不能将同时改变多个性质的输入当成单项机制检验。适用时给一个简单推导或极限条件，再说明仿真实际增加了什么：反馈作用、时序、阈值、变异、适用范围或与数据相容的反例。模型内条件性结论本身可以有价值，不强迫把每项结果包装成新发现。

关闭唯一输入通路后末端条件差为零，通常先证明实现符合所选结构；相同离散算法的另一写法、同种子重复和文件检查也各有有限作用。它们不能单独证明真实生物因果或数值收敛。主张某机制更能解释实际观察时，需有本轮可实施的竞争解释、独立扰动/观测或其他适用的判别依据。

需要区分多个候选时，先让它们与同一待解释表型及共同约束相容，再比较额外可测量差异及噪声；仅用任意不同参数产生两个不同幅值，不足以完成机制判别。不要求所有描述、理论或复现任务都建立模型集合。[判别能力的具体检查](run-compare-optimize.md#解释集合与判别能力)

**配平输入会改变比较所回答的问题。** 原始条件比较保留输入及反馈随修改而改变的后果；进一步把某项输入配平后，回答的是该匹配条件下还剩多少差异。若配平用于解释原始差异，两类比较并列保留。写明匹配的是计划输入还是实际送达量、逐细胞还是群体、参照时段与匹配误差；在参考网络事件下配平，并不保证修改后的网络自由运行时仍配平。依据实际运行检查相关量。

平均输入相同不保证波动、时间相关、反馈、绝对作用量或各亚群输入相同。重新分配输入也可能改变多个对象；列出仍有差异的量，说明哪些属于要研究的后果，不能一概消除。匹配后差异缩小或残留，只支持相应条件比较；没有进一步可识别性、交互和因果依据时，不能直接计算某机制的解释百分比或宣布真实生物直接效应。按问题选择必要对照，不把每个项目扩成全因子实验。

### 关键机制在正式统计窗内的作用

若结论依赖某机制在特定时段发挥作用，在 `review.questions[].required_mechanisms` 中列出机制 ID。对每个 ID，在同一问题的 `review.scientific_checks` 中登记 `kind="mechanism_activity"`、对应的 `mechanism_id` 和 `required=true`。在共用的 `description`、`basis_ref` 中说明所测量与声明作用的关系、窗口、采样间隔与作用阈值的依据。通用方法说明只能解释建模取舍。

计算前登记以下内容，运行后从对应文件重新计算。

| 登记内容 | 核对方法 |
|---|---|
| `source={run_ref,csv_ref,column,where?}` | 指定产生观测的正式运行、计划保存的原始 CSV 和实际读数列。`where` 按事前约定选择条件或实例。时序表中每个时刻应能定位到该实例的一个读数。 |
| `windows=[{id,start,stop}, …]`、`time_column,time_unit,max_gap` | 每个闭区间的首末值指计划纳入的首末采样时刻。`max_gap` 用同一时间单位规定可接受的最大相邻采样间隔。采用半开统计窗的工程可按记录时钟填写末个纳入时刻。 |
| `claim,direction,threshold,unit` | `above` 和 `below` 分别表示严格高于或低于预设阈值。`sustained` 要求每个窗两端均有观测，间隔符合约定，且每个采样时刻均满足幅度和方向。`occurrence` 只要求每个窗内有实际采到的达标时刻。 |
| 可选的 `control`、`control_change`、`pair_by` | 针对性对照沿用 `source` 的字段。`control_change` 说明改变的机制与配对依据。逐时刻计算主条件读数减去对照读数，再应用同一判据。两组时刻须对应。依赖相同实例、输入或重复时，用 `pair_by` 列出原始 ID 列核对配对。 |

例如，抑制在初始化时很强，进入正式窗后幅度已低于预设值，这组观测不足以支持持续抑制。短促脉冲可支持它在相应窗内出现过。针对性对照也可直接检验机制对下游读数的作用，无需把下游差异解释为机制本身的时序。逐窗结果保留样本数、达标数、观测范围、最大间隔与覆盖情况。持续作用的时间精度取决于采样间隔。

主条件和对照的 `run_ref` 须列入当前分析的运行清单、执行记录或相应比较/迭代记录。程序核对完成状态、模型版本、运行开始时保存的检查定义及该运行登记的输出文件。方法说明、配置、外部参考表和另一运行的同名输出均不足以确立本次作用。旧工程仍可按原约定复核历史资料。

## 比较与稳健性按主张安排

先保证协议、观测生成、单位、时间窗、独立单位和参考状态可比，再给误差或效应；不同条件的量级/方向参照可以报告，不能据此写成定量复现。校准、参与选模的数据和独立评价分别说明，模拟生成数据不能替代生物验证。

围绕会改变主结论的少量未知量安排有限比较：符号/路径、作用强度、投射比例、关键时间尺度或观测窗口等按实际模型选择，保留必要关联和边界。若合理参数下方向或排序翻转，报告有效窗口与不能裁决之处，不只展示有利值。随机种子、有限网络规模、参数不确定性和真实个体差异分别解释。

静息检查的时长和特征应足以支持本次所称的状态；单细胞、突触、网络与数值检查按[阶段要求](workflow-checks.md#从组件到完整网络)选择。多尺度模型分别核对积分、输入更新、跨模块交换和记录时钟；只减小一个模块步长不能代表其余时钟已经收敛。原算法的交叉实现与更细时间/空间分辨率的比较分开记录；对主要组间差异及阴性结论，落实[效应与判断检查](run-compare-optimize.md#主要效应的数值检查与阴性判断)，不能只看各条件分别运行平稳。

### 预注册比较与实际执行记录

在 `review.questions[].required_design_dimensions` 中列出本题依赖的比较维度 ID。每个 ID 在同一问题下须有 `required=true` 的 `comparison_design` 检查，`dimension_id` 与之相同。预处理、留出单位、真实与随机对照的搜索范围或重复数按研究问题选用。两个问题可各自使用相同维度。某一问题的数据或一项 `method_assumption` 无法覆盖另一问题声明的必需比较。

每项登记 `source`、`rule` 和 `expected`。`source` 沿用上表的已完成运行与原始 CSV 约定，指向逐次执行的操作、划分或候选运行清单。原始清单应包括实际尝试的候选及重复，记录顺序、身份和实际使用的数据。若实际比较另用了统计窗，可将执行清单上的窗口标识或边界列纳入设计检查。

| `rule` | `expected` 与实际核对内容 |
|---|---|
| `ordered_steps` | 预处理步骤名称的有序列表。`source.column` 读取实际步骤，`order_column` 读取执行次序。顺序改变即产生偏差。 |
| `disjoint_units` | 应有的划分标签列表。`split_column` 读取实际划分，`source.column` 读取受试者、批次等预定统计单位的原始 ID。按划分去重后查交集，并列出跨划分重复使用的单位。多折比较按折核对。预定了具体留出成员时，另用 `levels` 核对成员。 |
| `levels` | CSV 中应出现的完整标签集合，写成字符串列表。可检查实际处理方法、离散候选或完整参数组合。 |
| `observed_range`、`allowed_range` | 均登记数值上下界。前者核对实际尝试的最小值和最大值，后者检查尝试值是否落在允许范围内。覆盖离散网格还须核对具体候选。 |
| `distinct_count` | 应有的不同 ID 数。用原始清单中独立重复或随机化 ID 去重计数。同一重复的多个输出行只计一次。 |

例如，真实条件与随机对照应使用相同的搜索范围时，在同一维度中分别用 `source` 和 `control` 指定两组原始记录及各自的 `where`。两组各自满足 `rule` 和 `expected` 才算符合设计。若方案原定两组预算不同，分别登记相应条件与预期。若每个候选均需一定数量的重复，按条件和候选分别核对重复 ID。两组合并后的范围、计划重复数字段或最佳结果汇总表无法说明随机对照实际搜索了哪些候选。对照的可比性还取决于原始记录是否准确反映处理过程和独立单位，需结合相应代码和数据解释。

两类新检查均沿用 `completion_review.scientific_checks` 中同 ID 的结果行。机制逐窗得到支持可填 `accepted`。已完成且时窗覆盖充分、仍无法区分解释时可填 `inconclusive`，问题状态可如实记为同名状态。窗口缺测或所需比较尚未解决时填 `unresolved`，尚无可读输出可保留 `pending`。设计与原始记录一致可填 `accepted`，有偏差时用 `conditional` 限定仍成立的结论，或用 `unresolved` 保留原题未决。整组比较没有实际记录时，原题仍待完成。

有偏差或未定结果的完整记录填写 `reason,support_scope,evidence_refs,next_action,report_excerpt`。报告和待发送正文同时呈现偏差说明及 `support_scope` 所述结论范围，交付或决定停止时在 `completion_review.decision.scientific_check_ids` 中逐项引用。若必需设计有偏差但仍能作限定回答，问题的 `conclusion` 中也须包含这项 `support_scope` 原文。各字段与状态沿用[原有报告处置](project-checks.md)。

## 交付时按每项主张说明支持范围

| 实际完成的工作 | 可以说明什么 | 仍需什么才能作更强解释 |
|---|---|---|
| 假设下的有效模型/理论比较 | 在明确假设与范围下的关系、反例、预测 | 约束关键假设、适用数据和判别比较 |
| 与指定表型作可比定量比较 | 对所用条件/观测的再现及误差 | 独立条件评价；拟合成功不能单独确认病因 |
| 候选机制的实际判别 | 对已测试候选及条件的支持/反对、尚存解释 | 结论限于覆盖范围，不宣称排除了所有机制 |
| 可实现调控的响应/筛选 | 实际协议、映射、比较和约束支持的效果 | 功能、持续性或现实用途主张需对应观测与资料 |

按原始问题逐项作科研判断。核对资料质量和适用条件、目标机制在正式统计时段的实际作用、对照能否区分备选解释，以及效应大小与不确定性。充分的独立阴性检验可以回答预设预测，精度不足则保留未定。若原任务要求某项机制、拟合精度或独立支持，仍缺哪一项，就回到相应构建或比较环节处理。各项可支持的结论按实际条件并列报告。

最终正文直接交代关键依据、实际改动与结果支持范围；有调控时同时说明可控量、未知转导、匹配对照及实际改善/代价。方法、参数、图件和文字使用同一有效版本。[调控作用](regulation-design.md) · [科研交付](result-delivery.md) · [迭代记录](versioning.md)
