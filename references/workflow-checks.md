# 分阶段构建、判断与调整

用于把已选方法落实到可检查的模型。阶段按模型实际包含的机制选择；单细胞任务不建立虚构网络，无突触的模型不执行突触测试。已经有适用检查结果时直接引用，只重新检查改动影响的部分。以下要求由 AI 在已委托范围内执行，不为每个阶段增加用户审批。

开始实现或修改代码前，按[模型代码接入](skill-integrations.md#模型代码怎样衔接)采用 Ponytail 的复用与最小完整改动原则。科学要素、按网络组成拆分模块、实际运行及相关检查仍按本技能要求完成。

## 探索小运行与正式构建

选择执行深度时同时考虑任务范围、当前疑点和已有实现。下面区分的是工作范围，不新增脚本中的 `mode`、`features` 或成功标签。

| 本轮工作 | 运行前需要明确什么 | 保存与完成范围 |
|---|---|---|
| 讨论或定向调研 | 现象/问题、待决定差异、可查资料与本轮产物 | 在现有研究记录保存来源、选择、回答和缺口；不要求完整工程，也不产生虚构运行。 |
| 为选型做探索小运行 | 要区分的具体问题、最小对象与方程、必要参数及单位、初态/输入、目标读数、比较与计算预算 | 保留来源、实际代码/配置、命令/环境、随机设置、原始结果和判断。可以在当前方法或运行说明中简短记录，不先为未选定的最终网络填完全部文件。 |
| 完整网络方案与正式构建 | 当前科学目标、必要表示和参数可执行，条件/重复、观测、比较与资源明确 | 按原十四类、86 条事项和启用模块形成完整方法及结构化对应；正式运行前完成相应计划检查，交付前完成实际检查。 |
| 局部修改或结果重分析 | 受影响依赖、可复用版本/数据和本轮差异 | 沿用已有完整记录，只更新受影响条目；重分析不改写原仿真、不要求新建无关网络。 |

探索并不免除来源、单位、输入初态、数据用途和实际运行要求；只有探索产物，不能宣布完整模型交付。若探索结果进入正式结论，将实际代码、配置、来源和结果纳入正式记录，补齐适用检查；不能只改版本标签。原有完整工程中的小实验仍沿用其现有记录，不先删掉既有要求。

达到首次比较所需信息后即可在已授权范围内执行；仍需研究者决定的必要取舍保持待答，不以试运行名义锁定。正式网络的规模、协议和资源按局部试运行估计后确定。在试跑结束和扩展前，检查新发现是否产生应讨论的科学选择，按[分轮交流](interview.md)提出相关问题。

## 从研究目标确定必要结构

在当前构建方法中连接“观测量或待区分的解释 → 必需的细胞群、空间结构与机制 → 对照 → 可检验观察”。例如使用三维坐标时明确它是否参与连接、传导延迟、刺激定位或记录选择；只用于展示的位置不能支持空间机制结论。不同研究的数量、密度、体积、方程与连接规则先核对是否相容；相互排斥的设定形成不同候选方案，不能混成一套参数。

研究型任务按[科学问题与结果组织](result-delivery.md#让结果回答明确的科学问题)明确核心问题、假设及替代解释，提前确定主要比较与判断。逐项核对现有计算是否足以回答问题；机制结论缺少必要对照时补充授权范围内的比较，或明确尚不能区分，不能以稳定发放或拟合成功代替机制解释。

正式网络方案可将[构建模板](../assets/construction_plan.md)合并到 `docs/model_spec.md`；已有方法继续沿用，不重复生成方案。按[清单与模块规则](element-coverage.md)登记用户要求和目标依赖事项，全部详细事项均须有处理方式，启用模块均须有七项定义。改变观测量或机制时同步受影响的条目和检查；早期探索的记录深度按上节处理。

## 默认静息态与基础发放率

没有特殊要求时，构建目标是具有基础发放率的静息态网络。这里的静息态指没有额外任务刺激或干预的自发活动状态，保留模型所需且有依据的背景输入与回返活动；不等于把膜电位固定在静息电位或要求全网零发放。清醒安静、麻醉和离体等参考条件仍须明确，不能混用它们的目标范围。

1. **先确定各群体目标。** 按脑区、层次、细胞类型及参考状态调研基础发放率、个体分布和适用的活动特征，保存数值范围、单位、来源和统计口径。资料不足时明确暂定假设与依据，不把一个任意 Hz 数值设为所有模型的通用目标。
2. **说明基础活动怎样产生。** 按所选模型写清持续背景输入、噪声、网络回返或细胞内在机制及其参数；区分背景驱动与额外刺激。默认不增加任务刺激，也不因需要基础发放而机械加入某种可塑性或离子通道。背景输入可在有依据的范围内校准，实际输入与网络输出均需保存。
3. **实际运行并检查稳定性。** 运行时区分初始过渡与正式统计时段；根据模型时间尺度和试运行确定时长及稳定判断，比较相邻时窗、不同初始状态或适用的独立重复，检查持续漂移和异常活动。稳定指所关心的统计性质在规定范围内，不要求瞬时发放率恒定，也不将特定同步/振荡形式作为所有静息网络的统一条件。
4. **从输出计算基础发放率。** 脉冲网络按有效时窗内的真实尖峰数除以时长计算逐细胞率，再保存各群体均值、分布和静默细胞比例，注明分母、时窗和独立网络数。群体率模型报告其实际状态变量与定义，不能伪造尖峰。允许个别细胞或有限时窗内零发放，不强制每个神经元每次都产生尖峰。
5. **与参考比较后再交付。** 报告目标范围、实得率、随机波动及偏差。全网持续静默或主要群体偏离目标时，默认基础活动目标尚未满足：先查输入、单位、阈值、连接与数值设置，再按[优化规则](run-compare-optimize.md)处理并重跑，不用事后插入尖峰或只改图形来满足要求。低率群体记录太短、无法判断时如实说明，不能把有限时窗的零值直接当成永久静默。

静息态结果是默认必需交付。后续增加刺激或干预时，保留各条件对应的无额外刺激结果；如果干预改变基础状态，单列其变化。用户明确选择其他工作状态或特殊任务时，在方案中说明默认规则如何被替代。

正常参考与场景采用各自有依据的目标。特定条件下的静默、去极化阻滞或非平稳演化可能正是待研究结果；先区分实现/数值问题，再按该条件的证据评价，不能统一调回正常发放率。指定复现协议中的无自发活动也不自动修改。场景中初态、持续作用与历史按[时间协议](scenario-adaptation.md#参考模型与连续历史)说明，默认规则不增加未要求的刺激或干预。

## 数据用途在第一次使用时确定

在读取响应、选择模型或估计参数前，登记数据版本、独立样本单位、预定用途和划分规则。浏览数据格式、单位和样本清单可先于查看留出响应；只要响应已用于选模型、调参、筛选条件或设阈值，就记录为参与开发，不能重新标成独立检验。

同一动物、细胞、网络实例或连续试次的归属由研究问题决定，不能以拆行或拆时间点制造独立样本。拟合范围、预处理和判断标准冻结后再读取留出响应。留出表现不佳时保留结果；据此修改模型须说明原评价已参与开发，新的独立评价需要适当的新记录。数据不够时缩小可支持的结论范围，不伪造拆分或更换研究目标。

## 从组件到完整网络

将适用的阶段、标准、实际结果位置和剩余预算写入当前构建方法及进度。误差标准来自问题精度、测量误差或数值参考，在看到目标结果前确定。

下表服务于正式构建与相应交付；一次局部试验只执行与当前疑点相关的行。研究交流贯穿这些阶段，初始方案明确不代表后续不再讨论。

| 阶段 | 怎样检查 | 何时继续与失败时怎样处理 |
|---|---|---|
| 方法与参数 | 核对原清单全部详细事项、模块七项定义、来源条件、单位/转换、数据估计方法、群体规模、坐标及投射；完成方案完整性检查。 | 必需值或生成规则可执行，目标依赖模块无遗漏；待估量有可执行的估计协议与约束，缺失的科学决定保持待答，单位错误先修正。 |
| 输入与协议 | 按[输入检查](construction-methods.md#输入与实验协议也要检查)核对原始采样、转换、时钟与实际送达；相关检查可并入下列组件运行。 | 可以区分输入问题与模型响应；条件/时间不匹配先处理，不因异常输出直接扩大调参。 |
| 单细胞 | 用与目标相关的输入，检查初态、亚阈值响应、放电或其他目标状态；按模型需要核对解析解、参考实现或可比实测。 | 细胞响应和输出定义符合方程/协议；不适用的放电测试省略。错误先定位到细胞、输入或求解，不靠网络权重补偿。 |
| 单突触或细胞对 | 给定事件检查受体/耦合响应、幅度、时程、到达延迟、作用位置和单位；按需核对可塑性更新。 | 能区分突触机制、权重换算与事件调度问题，再将它们装入网络。不能仅凭“出现响应”判定正确。 |
| 小网络 | 从实际细胞与连接核对数量、三维范围、跨群投射、伙伴/接触关系、权重和延迟；检查缩放是否丢失必要群体/通路，运行相关配对对照。 | 相关通路与记录可以解释；按[执行管理](execution-management.md)测量构建、积分、保存等全过程成本，具备扩展条件。有错误先修组件或连接。 |
| 数值与规模 | 只改变步长，或适用时的区室划分等数值设置，比较主要量；网络缩放单列比较，不和数值精度混淆。 | 差异满足事先约定的精度与用途。放电时序敏感时说明是事件逐点比较还是统计量比较，不事后改标准迁就输出。 |
| 正式运行与初始比较 | 固定本轮方案、方法、数据用途及指标，实际运行规定条件与独立重复；按[运行与比较规则](run-compare-optimize.md)保存初始结果，定量比较适用文献和实测。 | 运行及输出完整，协议和观测量可比，误差可复算；缺真实数据时继续可行工作并单列待完成项。 |
| 优化与重新评价 | 定位偏差，在有依据的范围和预算内调整，每个候选重新运行；保留前后误差、分项指标、约束与选择理由，冻结后执行独立评价。 | 改善与未改善均如实报告；拟合数据不冒充独立检验，新配置不能引用旧输出。必要检查未完成不替换当前模型。 |
| 交付与续接 | 按[结果交付](result-delivery.md)组织每个构建步骤的实际产物与检查、主要科学比较及数据字典；重算主要指标和图，核对条件/重复与缺失状态，完成模块和输出检查。 | 必需步骤、模块或结果未完成时明确缺口；文件检查不能代替实际作用检查。失败更新不覆盖已通过检查的版本。 |

分别说明**实现是否一致、数值误差是否可接受、预测是否得到实测支持**。同一种子复跑一致只回答其中一部分。各模型按实际机制选择检查，避免为形式完整运行与目标无关的实验。

## 新发现返回哪里

| 发现 | 下一步及需要讨论的内容 |
|---|---|
| 来源单位、代码或实际输入不一致 | AI 回到参数/实现核对并修正，重跑受影响检查；不让用户投票决定正确单位。 |
| 当前表示不能表达目标量 | 回到方法与机制选择，比较最小必要修订；讨论解释层级或可接受简化，不无限调参掩盖缺失状态。 |
| 组件符合定义，进入网络后工作状态改变 | 核对实际输入、反馈、初态与数值；如形成新的机制/协议取舍，结合文献发起下一轮讨论，范围内技术修复继续执行。 |
| 目标数据缺失或协议不匹配 | 继续查适用数据，说明现有比较能支持什么；与研究者讨论保留目标等待材料还是另开探索，不能默默降低原目标。 |
| 多个候选无法区分或出现新现象 | 保存原结果，定向查找判别条件；集中讨论优先读数、可用材料和下一比较。 |
| 必须改变科学目标或超出约定资源 | 提供已完成结果与具体可选范围，再解决该取舍；不重新确认未变化的全部方案。 |

答案或新资料到来后，按[修改影响与复用](versioning.md#修改后哪些结果仍可使用)更新相应方法、参数、接口、运行与结论。输入偏差先回到输入及协议，单纯指标/图形修改先检查既有记录是否足够重分析；耦合动力学改动则沿依赖确定重算范围。不能忽略新发现，也不因一个局部变化重做全部研究。

## 关键假设与参数不确定性

从当前方案中选择会改变主要结论、来源有实质分歧或需要跨条件迁移的少数参数与构建假设。记录范围和依据、比较方法、观测量、固定条件、随机配对及预算，优先用小规模、少量有解释力的对照开展。不要机械遍历所有参数，也不要只选有利取值。

- 参数变化的比较尽量配对相同的网络与输入；独立种子用于另行描述抽样波动。保持条件所需的随机来源独立且标识明确。
- 关键参数可能相互补偿时补充针对性的组合变化；单参数扫描不能替代这种比较。
- 比较替代构建规则或去除某项机制时，保持其余条件可比，明确同时变化了哪些量。仅有模型对照的结论仍限于该模型。
- 多组参数或不同机制都能解释已有记录时，报告这些可能性及可以区分它们的新观察。不要将一个拟合最优值写成唯一的生理机制。
- 结论随合理设定改变时，说明成立条件；稳定时也只覆盖已检查范围。分析设置的敏感性与模型参数变化分开记录。

## 阶段结束与失败处理

每个阶段记录完成条件、实际结果、未解决问题、接下来的动作和已用预算。阶段状态可用“通过、未完成、不适用”，不适用项写科学或实现理由。预算分到调研、试运行、正式计算与分析，必要时包含内存和磁盘需求；续接时累计使用，不能每轮重新归零。

| 观察到的问题 | 优先检查 | 暂不执行的后续步骤 |
|---|---|---|
| 没有预期响应 | 实际输入目标与时刻、单位、记录选择、单细胞响应和相关投射是否存在 | 在问题未定位前扩大网络或盲目增大权重 |
| 活动或状态异常 | 方程与符号约定、单位换算、权重分布、初始状态、事件顺序和求解精度 | 用拟合掩盖实现错误 |
| 换步长或区室划分后主要结论变化 | 误差标准、求解与记录精度、事件/时窗对齐，按需细化设置 | 将未达到精度要求的结果用于机制判断 |
| 相同条件复跑不同 | 实际配置、随机流、生成顺序、并行设置、初始化及环境 | 直接把差异归为生物变异 |
| 留出评价未达标 | 原样记录误差与适用范围，再判断是否需要下一轮模型或数据 | 继续用同一留出响应调参却仍称独立验证 |
| 超过预算或信息不足 | 保存已完成内容、未决选择与继续所需资源，按已授权范围收束 | 默默扩大计算、下载或科学目标 |

## 检查技能本身是否有效

维护时先运行可重复的本地工具测试；涉及工作流变化时，再选适用的代表性任务检查产物。现有 [evals.json](../evals/evals.json) 中可优先使用：参数换算任务、虚拟空间网络、仅调研方法任务、带实测记录的校准任务。仅测试其中部分时明确范围。

数值工具测试用 [test_check_model.py](../evals/test_check_model.py)；清单与模块测试用 [test_check_elements.py](../evals/test_check_elements.py)，覆盖漏项、错标不适用、缺少模块定义或运行文件，以及方案/实施状态和只读行为。合成算例只检验软件，不证明生物学正确。多轮问答或自由调研的行为评测，需要实际完成对应任务并查看产物，不能根据提示词或字段齐全就宣布通过。没有独立评测条件时可做维护者执行的案例检查，并明确它与独立行为评测的区别。

输出交付工具测试用 [test_check_outputs.py](../evals/test_check_outputs.py)，覆盖逐步产物与依赖、遗漏条件、重复单位、空值状态、图件及设计记录引用、外部与模型数据区分、派生输入的完成状态和只读行为。执行 `python <skill_dir>/evals/test_check_outputs.py`，可加 `--report <尚不存在的输出文件>`。当前工具测试记录见 [latest-output-check-results.json](../evals/latest-output-check-results.json)；来源真实性、文献图适用性、二进制内容与图形显示仍需另行核对，不能由该测试推断已验证。

运行命令为 `python <skill_dir>/evals/test_check_model.py` 和 `python <skill_dir>/evals/test_check_elements.py`。需要保存报告时加 `--report <尚不存在的输出文件>`；工具不会覆盖已有报告。各工具当前结果分别见 [latest-check-results.json](../evals/latest-check-results.json) 与 [latest-element-check-results.json](../evals/latest-element-check-results.json)，核对记录的脚本版本和未运行范围，不能将旧报告用于新实现。

保存实际执行命令、测试输入性质、通过与失败项、发现的问题、修复和未运行范围。每个工具只保留一份当前评测记录，避免制造新的历史文件堆积。后续根据实际失败改进技能，不因想象中的问题不断增加通用规则。

完整流程执行检查用 [test_workflow.py](../evals/test_workflow.py)：实际构造并积分隔离的合成 LIF 网络，检查细胞、空间、连接、输入、事件和输出，随后执行参数改变后的新运行、仅重分析以及失败/过期记录的拒绝。运行 `python <skill_dir>/evals/test_workflow.py --report <新报告文件>`；`--workspace <新隔离目录>` 可保留可检查的完整示例。它是维护者执行的数值与工程测试，不是独立智能体评测或生物学验证。最新记录见 [latest-workflow-results.json](../evals/latest-workflow-results.json)。
