## 2026-11-24 续接网页与交互

新增的续接规则要求先恢复当前工程，再打开或刷新网页，随后调研与分批讨论；不等待新一轮参数方案确定。预览脚本返回当前对话可直接使用的 `open_request`，仍明确 `ready` 与浏览器已打开不同。新增本机测试检查续接时复用正确服务、显示更新后的目标与模型版本、保留原记录，以及明确关闭自动打开时不生成打开请求。情境库新增同义请求案例，属于可复用检查题，不据其存在宣称自由对话已全部验证。

页面按用户后续明确要求采用平板/桌面宽度：内容上限 1120 px，宽度足够时模型组成和验证状态并排，方法、图件及报告使用完整内容宽度。借鉴 [Apple 当前 iOS 展示](https://www.apple.com/os/ios/)、[材质规范](https://developer.apple.com/design/human-interface-guidelines/materials)及[动态反馈规范](https://developer.apple.com/design/human-interface-guidelines/motion)。玻璃效果仅用于少量控件；保留清楚的内容、明暗外观、减少动态和减少透明选项。使用系统字体与本地 CSS/JavaScript，无 Apple 资源拷贝、外部脚本、字体或新增运行库。

实际检查由主 agent 在当前 Codex 完成，网页实现由工作 agent 独立提交后冻结：

- 关闭测试项目标签后，从 `resume` 入口重新打开同一工程；服务地址被复用，实际工程名正确，未触发模型重跑。已运行例子来自隔离 10 神经元 LIF 网络的一次 500 ms 积分，具有 26 条连接和 180 个发放事件；仅检查软件与显示，不作生物学判断。
- 观察了原窗口、390 px 兼容布局和最终 1024 px 平板布局；最终保留宽版。检查浅色及系统深色、偏好保存、减少动态/透明、连续折叠操作、键盘展开、Escape 关闭及焦点返回、实际图件放大和原始大小切换。未见页面 JavaScript 错误或最终布局横向溢出。
- 六项报告保持原顺序；缺失片段明确尚未完成，未确认的科学状态无完成标记。下载链接内嵌报告与原 Markdown 字节一致；本宿主下载事件等待未返回，因此未宣称已验证文件保存完成。
- 工作流 221 项检查通过，包含查看页 13 项及本机预览 9 项；其余发布检查沿用原五套命令。JavaScript 语法、原 ID、离线资源和两段脚本结构也已检查。测试产物与实际源码对应见[当前工作流记录](latest-workflow-results.json)。

未验证原生 iPad/iPhone、Safari、所有系统无障碍设置、打印输出及长期自由对话中的必然执行；界面是对设计原则的网页适配。页面仍只展示已保存记录，不是实时仿真监控，也不取代六项科研答复。自动打开是技能在支持的宿主内执行的动作，不是监听任意聊天的全局程序。

## 文字及显示检查

2026-11-23 新增一份统一表达适配，覆盖正文、提问、表格、图内文字、图注与网页；与 anti-defensive-writing 分工，保留原六项顺序和科学含义。三个写作来源的固定版本、许可与适配文件已纳入原来源检查；未安装完整上游工具包。

- 独立 agent 从原要求、原 anti-defensive-writing 和实际文件差异复核，发现并修正了两处语义变化：已检查但无法确认的状态不能写成“尚未检查”，D0 的说明不能省略负面影响条件。状态判断分支保持不变。
- 两条定向表达试用分别检查刺激响应细胞比例及固定参数后的新随机实现。改写保留 40/100、60/100、至少 70% 的目标及未达到要求；保留 6 次新网络实现的含义，没有改写成生物样本、功能恢复或实验验证。这是给定条件的文字试用，未运行新的科研模型。
- 主 agent 使用明确标注的合成计数生成图和表，实际查看中文标题、坐标轴、单位、图例、表头与图注；没有观察到缺字、遮挡或截断。两组比例保持 40% 和 60%，均未达到 70% 要求。检查材料只用于表达和显示，不能作生物学结果。

本次没有开展真实用户理解度调查、跨模型稳定性测试或三种写作技能的对照评测；上述定向试用不能证明所有后续输出都符合规范。脚本检查不能替代对实际文字和图件的阅读。

## 从实际失效到修改

| 已发现的问题 | 当前处理 | 实际检查 |
|---|---|---|
| 六项片段虽然出现，中间问题仍可挤掉或打断完整正文 | 保存完整分节正文，按原顺序组装发送稿，补充答复只能追加；单独核对报告与对话 | 拒绝替换、前置、插入、漏答及摘要前另加一段；允许六项后的补充答复 |
| 图或公式放在别处，也被当作该部分齐全 | 图、公式按所属部分检查，与原始运行和数值核对共用 | 拒绝方法图、公式出现在错误部分 |
| 配置状态或粘贴表格即可显示完成 | 从实际构建与检查记录生成标记；完整交付需要适用模型部分的实际步骤和方法说明 | 拒绝无构建记录、缺方法说明、非法 `verified`、不是真正布尔值的完成标志 |
| 交付缺表已判失败，页面仍保留此前的成功 | 失败后重新生成当前真实状态，补稿用表与实际结果分开 | 缺表时交付不打勾；补入并复核后才改变相应状态 |
| 网页把保存的记录表现成实时工作或科学成功 | 明示只读、已保存记录；分开构建、五项科学判断、图与正文 | 实际打开 Codex 页签，确认“合成独立评价未获支持”无对钩，另外两模块明确未纳入本轮 |

规则沿用一套任务计划、构建步骤与分析记录，没有增加第二个可编辑状态表。开始、阶段转换、恢复及最终交付读取适用记录；显式停止、取消或范围改变仍尊重用户决定，普通进度消息不重复整份科研报告。

当前宿主实际验证：从只有任务计划的隔离工程生成页面，`open_in_codex` 省略 `threadId` 返回 queued 后，进一步读取浏览器实际页面，确认其工程名对应本次项目，所有未做事项均未打钩。未用“请求已接受”替代已打开。该验证覆盖本机当前宿主及明确的阶段动作，不等于所有未来自由对话都必然加载技能或执行工具；其他宿主没有浏览器能力时按说明保留 HTML。

主 agent 负责交付规则、整体测试和发布；两个工作 agent 分别实现状态展示与网页；未负责实现的 agent 查看原要求及产物，首先发现上述四类完成判断缺陷并交回修复。角色按依赖先后开展，不并发修改同一文件；本轮不能据此量化多 agent 相对单 agent 的普遍收益。

## 可视化文档的采用范围

采用执行状态、信息视图和查看模式分开；读取既有产物、缺失不造图、保存重开不等于续算、网页不控制求解器。普通流程展示用标准库导出离线 HTML，不为少量状态和原图强制安装三维平台。需要复杂数据交互或真实空间量时再选择相应库；本轮仅查询了相关官方接口，没有宣称已集成实时或三维后端。

尚未验证：连续批次自动刷新、三维对象查询、远程计算连接、求解器中断恢复，以及长期自由多轮对话中宿主最终实际消息始终遵守格式。`--response-output` 能导出已核查正文，但不能拦截宿主发送其他文本；最终仍由主 agent 使用该正文并核对核心科学解释。自由文字的真实性、实验可比性和方法合理性也不能由格式工具自动判断。
